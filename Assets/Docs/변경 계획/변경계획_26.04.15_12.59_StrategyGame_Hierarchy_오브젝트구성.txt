d. [Manager] 기준 추가 가능 오브젝트
================================================================

  [ 현재 C 조합: 추가 대상 없음 ]

  C 조합(③+⑤+⑦+⑧)에 필요한 모든 MonoBehaviour 오브젝트는
  이미 씬에 배치되어 있다. 새 GameObject를 만들 필요 없음.

  단, 아래 Inspector SO 연결이 미완성이면 즉시 연결해야 한다.

  ─────────────────────────────────────────────────────────────
  [ 즉시 해야 할 것: Inspector SO 연결 ]
  ─────────────────────────────────────────────────────────────

  ① SGManager (GameManager)
     - DefaultGameState 필드 → GameStateSO 인스턴스 연결
     - 없으면: NewGame() 또는 LoadData() 시 NullRef

  ② DayManager
     - _dayCharacterManager 필드 → DayCharacterManager 오브젝트 드래그
     - _defaultDaySO 필드 → DaySO 인스턴스 연결
     - 없으면: StartDay() 시 즉시 에러

  ③ CharacterLevelDatabase
     - _levelDescriptionSOs 목록 → PlayerLevelSO 인스턴스 추가
     - 없으면: Guild.HandleDayReport() 에서 레벨업 판정 불가

  ─────────────────────────────────────────────────────────────
  [ B 조합 추가 시: [Manager] 하위에 넣을 수 있는 오브젝트 ]
  ─────────────────────────────────────────────────────────────

  ④ PathFinder (PathFinderManager.cs) - 아직 스크립트 없음
     위치: [Manager] 하위 또는 독립
     역할: BFS 기반 경로 탐색 (맵 이동 로직)
     의존: 없음 (독립 시스템)

  ⑤ SoundManager (SoundManager.cs) - 아직 스크립트 없음
     위치: [Manager] 하위
     역할: BGM/SFX 재생 관리 싱글턴
     의존: 없음 (독립 시스템)

  ─────────────────────────────────────────────────────────────
  [ A 조합 추가 시: [Manager] 하위에 넣을 수 있는 오브젝트 ]
  ─────────────────────────────────────────────────────────────

  ⑥ DayMissionManager (DayMissionManager.cs) - 아직 스크립트 없음
     위치: [Manager] 하위 (DayManager의 자식 또는 형제)

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  Q. [Manager] 하나에 전부 자식으로 두는 이유?
  ──────────────────────────────────────────────
  ✅ 장점:
  - Hierarchy 상단에서 Manager 그룹을 접고 펼칠 수 있어 가독성 높음
  - 씬에 오브젝트가 많아질 때 Manager 계층 구분이 명확
  - DontDestroyOnLoad를 [Manager] 하나에만 적용하면
    모든 자식이 씬 전환 시 자동으로 유지됨 (선택 사항)

  Q. DayCharacterManager를 DayManager의 자식으로 두지 않는 이유?
  ────────────────────────────────────────────────────────────────
  ✅ Inspector 드래그로 연결하므로 부모-자식 관계가 필요 없다.
  씬 구조는 flat하게 유지하고 참조는 SerializeField로 처리하는
  GameDispatchLike 원본의 패턴을 따른다.

  Q. CharacterDatabase를 Resources 기반으로 처리하는 이유?
  ──────────────────────────────────────────────────────────
  ✅ CharacterSO는 게임 데이터(캐릭터 수십 개)이므로
  Inspector에서 수동 연결하면 관리가 매우 번거롭다.
  Resources.LoadAll<CharacterSO>("StrategyGame/Characters") 방식은
  폴더에 SO만 추가하면 코드 수정 없이 자동 인식된다.

  변경 위치: Assets/Scenes/Strategy game.unity (Inspector 연결만)
  ─────────────────────────────────────────────────────

  - CharacterSO 인스턴스 1개 이상

h. 주의할 점
================================================================

  ① CharacterSO는 반드시 Resources/StrategyGame/Characters/ 에 배치
  ─────────────────────────────────────────────────────────────────
  CharacterDatabase.Awake()가 StrategyGamePaths.Characters 경로
  ("StrategyGame/Characters")에서 Resources.LoadAll로 로드한다.
  이 경로 밖에 있으면 CharacterDatabase가 빈 딕셔너리가 되어
  FactoryCharacterUnit.CreateCharacterUnit() 시 null 반환.

  ② DayManager._dayCharacterManager는 Inspector 연결 필수
  ─────────────────────────────────────────────────────────────────
  DayManager.StartDay()가 _dayCharacterManager.Init()을 호출한다.
  연결 없으면 StartDay() 첫 줄에서 NullReferenceException 발생.

  ③ PlayerLevelSO가 0개이면 Mathf.Clamp 인덱스 에러 발생
  ─────────────────────────────────────────────────────────────────
  CharacterLevelDatabase.GetLevel(0) 호출 시 빈 목록이면
  IndexOutOfRangeException. 최소 레벨 0, 1 두 개를 만들어 연결할 것.

  ④ DaySO의 DayDurationInSeconds는 테스트 시 짧게 설정
  ─────────────────────────────────────────────────────────────────
  Phase C에서는 DayDurationInSeconds만큼 실시간으로 기다린다.
  처음 테스트 시 5~10초로 설정해 하루 종료 이벤트가 발행되는지 확인.
  운영값은 검증 후 조정.

  ⑤ [Manager]에 DontDestroyOnLoad 적용 시 씬 전환 주의
  ─────────────────────────────────────────────────────────────────
  현재는 씬이 1개(Strategy game.unity)이므로 문제 없다.
  Visual Novel ↔ Strategy Game 씬 전환을 구현할 때,
  [Manager]에 DontDestroyOnLoad를 적용하면 씬 전환 후 중복 생성
  방지를 위한 추가 처리가 필요하다.

  ⑥ B/A 조합 추가 전 C 조합 완전 동작 확인 필수
  ─────────────────────────────────────────────────────────────────
  Inspector 연결이 완료되고 플레이 테스트에서 에러 없는 상태를
  확인한 후에 다음 조합을 추가할 것.
  에러가 있는 상태에서 오브젝트를 추가하면 원인 추적이 어려워짐.

[ 즉시 실행 가능한 첫 번째 액션 ]

  1. Assets/Configuration/StrategyGame/ 폴더에서
     우클릭 → Create → StrategySystem/Game State → GameStateSO 생성

  2. 우클릭 → Create → StrategySystem/Day → DaySO 생성
     DayDurationInSeconds = 10 (테스트용)

  3. 우클릭 → Create → StrategySystem/Player Level → PlayerLevelSO 2개 생성
     Level_0: ExpToLevelUp = 100
     Level_1: ExpToLevelUp = 300

  4. Assets/Resources/StrategyGame/Characters/ 폴더 생성 후
     우클릭 → Create → StrategySystem/Character → CharacterSO 1개 생성

  5. 씬에서 각 Inspector 연결 (Step 1-3 ~ 1-5)

  6. 플레이 → Console 에러 0 확인
