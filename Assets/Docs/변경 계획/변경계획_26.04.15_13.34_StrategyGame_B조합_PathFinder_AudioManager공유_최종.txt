b. 요구한 기능
================================================================

  [ B 조합 최종 구성 ]

  ① PathFinder (경로탐색) ← GameDispatchLike에서 복사
     - 씬에 Node 오브젝트들을 배치하고 연결해
       두 Node 사이의 최단 경로를 BFS로 계산
     - GetPath(Node origin, Node dest) → List<Node>
     - 캐릭터/유닛의 맵 이동 경로 계산에 활용
     - 노드 간 양방향/단방향 설정 가능

  ② Audio ← VisualNovel의 AudioManager 공유 (새 파일 복사 없음)
     - BGM: 채널 단위 재생, 트랙 전환 시 자동 페이드 인/아웃
     - SFX: 동적 AudioSource 생성, 재생 완료 후 자동 Destroy
     - 볼륨: ConfigMenu 설정(SetMusicVolume 등)이 StrategyGame에도 동일 적용
     - GameDispatchLike의 SoundManager.cs / TriggerSFX.cs 는 사용하지 않음

  [ 특징 ]
  - B 조합 두 시스템 모두 C 조합에 전혀 의존하지 않음 → 독립 추가/테스트 가능
  - 오디오는 기존 AudioManager를 공유하므로 신규 스크립트 파일 추가 없음

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  [ PathFinder: 프리팹 없이 직접 배치하는 이유 ]
  ──────────────────────────────────────────────
  ✅ B 조합 단계의 목적은 "경로 계산이 동작하는지 검증"이다.
     프리팹 제작과 맵 설계는 ⑨ UI/View 조합 시점에 진행하는 것이 효율적.
     지금은 Inspector 직결로 최소 구성만 만들고 동작 확인에 집중한다.

  [ 오디오: SoundManager 대신 AudioManager를 공유하는 이유 ]
  ──────────────────────────────────────────────────────────

  방법 A: GameDispatchLike SoundManager.cs 복사
  ─────────────────────────────────────────────
  - 기능: 라운드로빈 AudioSource 풀, BGM/SFX 기본 재생
  단점:
    ▸ 이미 프로젝트에 AudioManager가 있어 오디오 관리 시스템이 둘로 나뉨
    ▸ AudioMixer 미사용 → ConfigMenu 볼륨 설정이 StrategyGame 사운드에 미적용
    ▸ 씬 전환 시 BGM 끊김 (DontDestroyOnLoad 없음)
    ▸ 페이드 인/아웃 없음
  → ❌ 채택 안 함

  방법 B: VisualNovel AudioManager 공유 ✅ (채택)
  ──────────────────────────────────────────────
  장점:
    ▸ 새 파일 복사 없음 → 코드량 증가 없음
    ▸ AudioMixer 공유 → ConfigMenu 볼륨 설정 전체 게임에 통일 적용
    ▸ DontDestroyOnLoad → 씬 전환 시 BGM 자연스럽게 유지/전환
    ▸ 페이드 트랜지션, 채널 관리, Voice 지원 포함
    ▸ AudioManager.instance 하나로 전체 프로젝트 오디오 통일
  단점:
    ▸ AudioManager.cs가 VisualNovel 폴더에 있어 공유 자산임이 덜 명확
      (추후 Common 폴더 이동 고려 가능, 지금은 하지 않음)
  → ✅ 채택

h. 주의할 점
================================================================

  ① Node.cs 수정 2건은 복사 직후 즉시 처리
  ──────────────────────────────────────────────────────────────
  ▸ using UnityEngine.Experimental.GlobalIllumination 미제거 시
    Unity 6에서 경고 또는 에러 발생 (네임스페이스 deprecated)
  ▸ _circle null 체크 미처리 시 Node를 씬에 배치하는 즉시
    OnValidate가 실행되어 에디터 Console에 NullRef 에러 출력
    (런타임 에러는 아니지만 다른 에러와 혼동되므로 반드시 처리)

  ② AudioMixerGroup 3개 모두 연결 필수
  ──────────────────────────────────────────────────────────────
  SetMusicVolume() / SetSFXVolume() / SetVoicesVolume() 호출 시
  미연결 mixer가 있으면 NullReferenceException 발생.
  현재는 ConfigMenu가 이 메서드들을 자동 호출하는 구조이므로
  씬 열자마자 에러가 날 수 있다.
  Main Menu.unity의 Audio Manager Inspector 설정을 그대로 맞출 것.

  ③ audioFalloffCurve 빈 커브 주의
  ──────────────────────────────────────────────────────────────
  SetMusicVolume()이 audioFalloffCurve.Evaluate(volume)을 호출한다.
  AnimationCurve가 키 없음(기본값)이면 항상 0을 반환 → 소리가 항상 최소.
  Main Menu.unity의 AudioManager와 동일한 커브 설정 필요.

  ④ PathFinderManager.nodesParent 미연결 시 동작 주의
  ──────────────────────────────────────────────────────────────
  nodesParent == null이면 Start()에서 자동으로 자신(transform)을 nodesParent로 사용.
  [Nodes]를 별도 오브젝트로 만든 경우 반드시 nodesParent에 연결할 것.
  연결 안 하면 PathFinderManager가 [PathFinder] 자신의 자식을 노드로 인식 →
  노드가 하나도 없어 GetPath() 항상 빈 리스트 반환.

  ⑤ DontDestroyOnLoad로 인해 Play 재시작 시 Audio Manager 중복 발생 가능
  ──────────────────────────────────────────────────────────────
  에디터에서 Play → Stop → Play 할 때마다 DontDestroyOnLoad 오브젝트가
  누적될 수 있다. AudioManager.Awake()가 DestroyImmediate로 중복 제거를
  처리하므로 기능상 문제는 없으나, Console에 경고가 출력될 수 있다.
  이는 에디터 환경 특성으로 빌드 후 실제 실행 시에는 발생하지 않는다.

  ⑥ SoundManager는 이후에도 추가하지 않음
  ──────────────────────────────────────────────────────────────
  이 계획 실행 후 StrategyGame 오디오 = AudioManager로 확정.
  A 조합, UI 조합 등 이후 작업에서도 오디오가 필요하면
  반드시 AudioManager.instance를 사용한다.
  SoundManager를 추가하면 관리 시스템이 둘로 나뉘어 혼란이 생긴다.

  ⑦ 각 Phase 완료 후 Console 에러 0 확인 후 다음 진행
  ──────────────────────────────────────────────────────────────
  에러 상태에서 씬 저장 또는 Unity 종료 시 씬 파일 손상 가능.
  PHASE 7-2 컴파일 확인을 반드시 통과한 후 씬 작업을 시작한다.
