b. 요구한 기능
================================================================
  GalleryMenu.cs의 ConstructNavBar() 실행 결과로,
  NavBar 컨테이너 내 자식 오브젝트(버튼)가 아래 순서로 배치되어야 한다.

    1. LeftEndButton
    2. previousButton
    3. [panelSelectionPrefab 기반으로 생성된 페이지 버튼들]
    4. nextButton
    5. RightEndButton

  즉, previousButton이 생성된 페이지 선택 버튼들보다 앞에 와야 한다.


================================================================
c. 현재 상황 및 코드
================================================================

[씬 계층 구조 (NavBar 자식 순서 추정)]
  0: LeftEndButton
  1: panelSelectionPrefab   ← 템플릿 (비활성 상태로 존재)
  2: previousButton
  3: nextButton
  4: RightEndButton

[ConstructNavBar() 실행 후 자식 순서]
  Instantiate(panelSelectionPrefab.gameObject, panelSelectionPrefab.transform.parent)
  → 새 오브젝트는 부모의 마지막 자식으로 추가됨

  0: LeftEndButton
  1: panelSelectionPrefab (비활성)
  2: previousButton
  3: nextButton
  4: RightEndButton
  5: [생성된 페이지 버튼 1]
  6: [생성된 페이지 버튼 2]
  ...

  이후 RightEndButton.transform.SetAsLastSibling() 호출로:
  0: LeftEndButton
  1: panelSelectionPrefab (비활성)
  2: previousButton
  3: nextButton
  4: [생성된 페이지 버튼 1]
  5: [생성된 페이지 버튼 2]
  6: RightEndButton

  → previousButton이 생성 버튼보다 앞, nextButton이 생성 버튼보다 뒤에 있어서
    원하는 순서와 다름

[관련 코드 - GalleryMenu.cs, ConstructNavBar()]
  private void ConstructNavBar()
  {
      int totalImages = galleryImages.Length;

      maxPages = Mathf.CeilToInt((float)totalImages / previewsPerPage);
      int pageLimit = PAGE_BUTTON_LIMIT < maxPages ? PAGE_BUTTON_LIMIT : maxPages;

      for(int i = 1; i <= pageLimit; i++)
      {
          GameObject buttonOB = Instantiate(panelSelectionPrefab.gameObject, panelSelectionPrefab.transform.parent);
          buttonOB.SetActive(true);

          Button button = buttonOB.GetComponent<Button>();
          TextMeshProUGUI buttonText = button.GetComponentInChildren<TextMeshProUGUI>();

          buttonOB.name = i.ToString();
          int page = i;
          button.onClick.AddListener(() => LoadPage(page));
          buttonText.text = i.ToString();
      }

      previousButton.gameObject.SetActive(pageLimit < maxPages);
      nextButton.gameObject.SetActive(pageLimit < maxPages);
      RightEndButton.transform.SetAsLastSibling();   // ← 현재 유일한 순서 보정
  }


================================================================
d. 요구한 기능을 구현하기 위한 변경 방법
================================================================

[변경 전략]
  ConstructNavBar() 내부에서 루프 종료 후,
  SetSiblingIndex / SetAsLastSibling을 사용해
  nextButton과 RightEndButton을 명시적으로 뒤로 밀어 순서를 확정한다.

[변경 후 ConstructNavBar() 추가 코드]
  루프 종료 후 아래 두 줄을 기존 SetAsLastSibling() 앞에 삽입:

      nextButton.transform.SetSiblingIndex(nextButton.transform.parent.childCount - 2);
      RightEndButton.transform.SetAsLastSibling();

  실행 후 자식 순서:
    0: LeftEndButton
    1: panelSelectionPrefab (비활성 템플릿)
    2: previousButton
    3: [생성된 페이지 버튼 1]
    4: [생성된 페이지 버튼 2]
    5: nextButton          ← childCount-2 위치로 이동
    6: RightEndButton      ← 마지막으로 이동

  ※ panelSelectionPrefab은 비활성 상태이므로 UI 상 표시되지 않음
     시각적으로는: LeftEnd → previous → [페이지버튼들] → next → RightEnd


================================================================
e. 다른 방법들과 비교 / d 방식 선택 이유
================================================================

[방법 1] Unity 씬에서 직접 계층 순서 변경 (panelSelectionPrefab 위치 이동)
  → 씬 에디터에서 panelSelectionPrefab을 previousButton과 nextButton 사이로 이동
  → Instantiate 후 오브젝트가 panelSelectionPrefab 바로 다음에 생성되므로,
     nextButton/RightEndButton을 뒤로 밀어야 하는 건 동일
  → 코드 변경도 결국 필요하므로 단독으로는 해결되지 않음

[방법 2] 각 버튼 생성 직후 SetSiblingIndex로 삽입 위치 지정
  → 루프 내에서 nextButton의 현재 인덱스를 추적하며 삽입
  → 매 반복마다 인덱스 재계산이 필요해 복잡도가 증가함
  → 유지보수 시 혼란 가능성 있음

[방법 3 - 선택: d] 루프 종료 후 nextButton/RightEndButton을 뒤로 밀기
  → 기존 코드 흐름(루프 → 후처리)을 유지
  → 기존 RightEndButton.SetAsLastSibling() 패턴과 일관성 있음
  → 코드 변경이 최소화되고, 의도가 명확함
  → 씬 계층 구조 변경 없이 순수 코드만으로 해결 가능

  → 따라서 d 방식 채택
