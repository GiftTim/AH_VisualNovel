  using Microsoft.Unity.VisualStudio.Editor;
  using UnityEngine;

  public enum BuildingType
  {
      HQ,      // 본부건물
      Normal,  // 기본 건물
  }

  public enum BuildingState
  {
      Idle,        // 대기 중인 건물
      Incident,    // 사건 발생 건물
      Unselected,  // 선택 안 된 건물 (미션 만료)
      Selected,    // 선택된 건물 (미션 진행 중)
      Completed    // 사건 완료 건물
  }

  [System.Serializable]
  public class SpotVisualConfig
  {
      public BuildingType _buildingType;
      public BuildingState _buildingState;
      public Image _icon;
      public Color color = Color.white;
      public Sprite sprite;
  }

  public class Spot : MonoBehaviour
  {
      [SerializeField] BuildingType _spotType;
      public BuildingType SpotType => _spotType;

      public void SetType(BuildingType type)
      {
          _spotType = type;
      }
  }

  [LineRenderer vs UI Line (Canvas DrawLine)]
  - LineRenderer
    * 장점 : 두께·색상·텍스처를 Material로 자유롭게 제어 가능
             AnimationCurve로 선 폭 변화 연출 가능
             추후 캐릭터 이동 경로 시각화에 자연스럽게 연동 가능
    * 단점 : ScreenSpace-Camera Canvas와 좌표계가 달라
             월드 좌표 변환이 필요 (RectTransformUtility 사용)

  - UI Image (Sliced/Tiled) 로 선을 흉내내는 방식
    * 장점 : UI 좌표계 안에서 단순
    * 단점 : 각도 계산이 번거롭고, 두께 제어 불편,
             추후 캐릭터 이동 연동 시 LineRenderer로 교체 필요성 높음

  → 추후 캐릭터 이동 연동을 고려할 때 LineRenderer가 더 확장성 있으므로 선택

  [동적 생성 vs 씬에 미리 배치]
  - 동적 생성
    * Building 수가 달라질 때 코드 수정 없이 자동 대응
    * Inspector에서 Building 오브젝트만 배치하면 됨
    * 단점 : 씬 구조가 런타임에 결정되어 디버깅·확인이 어려움
  - 씬 미리 배치 (채택)
    * 건물 수를 기획 단계에서 고정하여 씬에 직접 배치
    * LineRenderer 오브젝트도 씬에 미리 생성해 Inspector에서 연결
    * 씬 계층 구조를 에디터에서 바로 확인·수정 가능
    * Building 수 변경 시 씬에서 오브젝트와 Inspector 연결만 추가/삭제하면 됨

  → 건물 수가 고정되어 있으므로 씬 미리 배치 방식 채택

  [Screen Space - Camera vs Screen Space - Overlay vs World Space]
  - Screen Space - Camera
    * 카메라 기준 렌더링으로 Post-Processing 효과 적용 가능
    * LineRenderer(월드 공간)와 동일 카메라를 공유하므로 좌표 변환 일관성 확보
  - Screen Space - Overlay
    * 가장 단순하나 LineRenderer와 깊이 정렬이 분리됨
  - World Space
    * 해상도 독립적이지만 UI 배치가 까다로움

  → Screen Space - Camera 선택

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. [좌표계 변환]
     LineRenderer는 월드 공간(World Space)에서 동작하고,
     Canvas(Screen Space - Camera)의 RectTransform은 캔버스 로컬 좌표계를 사용한다.
     → RectTransformUtility.LocalPointToWorldPoint 또는
       RectTransform.position (월드 좌표 직접 접근) 을 사용해야 한다.
     → RectTransform.anchoredPosition 을 그대로 쓰면 선이 엉뚱한 위치에 그려진다.

  2. [Canvas의 Render Camera 미할당 시 오작동]
     Screen Space - Camera 모드에서 Render Camera를 비워두면
     Canvas가 Screen Space - Overlay처럼 동작하여
     LineRenderer와 렌더 순서가 어긋날 수 있다.
     → 반드시 Camera 오브젝트를 할당할 것.

  3. [LineRenderer의 Sorting Layer / Order]
     LineRenderer는 기본적으로 Default Sorting Layer에 배치된다.
     Canvas UI 위에 그릴지 아래에 그릴지에 따라
     LineRenderer의 Sorting Layer와 Order in Layer를 조정해야 한다.
     → Panel_2_Building 위, Panel_3_Character 아래에 표시하려면
       Canvas의 Order in Layer 값 사이에 LineRenderer Order를 맞출 것.

  4. [SpotVisualConfig 내 Image 타입 충돌]
     현재 Spot.cs에 using Microsoft.Unity.VisualStudio.Editor 가 있어
     Image가 UnityEngine.UI.Image가 아닌 에디터 전용 타입을 참조할 수 있음.
     → Spot.cs 수정이 반드시 선행되어야 한다.

  5. [HQ가 반드시 1개여야 하는 제약]
     BuildingLineConnector는 HQ가 1개임을 가정하고 구현한다.
     씬에 HQ가 0개이거나 2개 이상이면 Debug.LogError로 알리고 중단할 것.

  6. [Building 수 변경 시 씬 편집 필요]
     건물 수를 고정·미리 배치하는 방식이므로,
     Building을 추가/삭제할 경우 씬에서 직접 오브젝트를 추가하고
     BuildingLineConnector의 Inspector 배열도 함께 갱신해야 한다.
     → buildingSpots 배열과 lineRenderers 배열의 길이를 항상 동일하게 유지할 것.

  7. [Panel_3_Character는 이번에 기능 없음]
     Panel_3_Character는 계층 구조만 생성하고 기능 스크립트는 붙이지 않는다.
