================================================================================
c. 변경 후 작동 흐름
================================================================================

  대화 한 줄이 처리되는 전체 흐름 (주석으로 각 단계를 설명함):

  1. DialogueSystem.Say() / Say(Conversation)
     └─ ConversationManager.StartConversation()
           └─ RunningConversation() [코루틴 시작]

  2. RunningConversation() 루프 (ConversationQueue가 빌 때까지)
     ├─ currentConversation.CurrentLine() → rawLine 획득
     ├─ DialogueParser.Parse(rawLine) → DIALOGUE_LINE 생성
     │    ├─ RipContent() → speaker / dialogue / commands 분리
     │    │    (4가지 분기: 명령어만 / 대화+명령어 / 명령어 앞 / 순수 대사)
     │    └─ TagManager.Inject(commands) → 명령어 태그/변수 치환
     │
     ├─ logicalLineManager.TryGetLogic() → choice/if/input 처리
     │
     ├─ [대화가 있으면] Line_RunDialogue()
     │    ├─ HandleSpeakerLogic() → 캐릭터 등장/위치/표정/이름/스타일 설정
     │    └─ BuildLineSegments() → 세그먼트 순서대로 텍스트 출력
     │         ├─ WaitForDialogueSegmentSignalToBeTriggered()
     │         │    (NONE/C/A/WA/WC/N 각 신호에 따라 대기 방식 결정)
     │         └─ BuildDialogue() → TextArchitect로 타이핑 출력
     │              (클릭 1회: hurryUp, 클릭 2회: ForceComplete)
     │
     ├─ [명령어가 있으면] LINE_RunCommands()
     │    (waitForCompletion=true: 완료 대기, false: fire-and-forget)
     │
     └─ [대화가 있었으면] WaitForUserInput()
          → prompt.Show() → 사용자 클릭 대기 → prompt.Hide()
          → OnSystemPrompt_Clear() (onClear 이벤트 발생)

  1. DialogueParser.cs - TagManager.Inject 이중 호출
     - Parse() 내에 TagManager.Inject(commands) 가 두 번 호출됨.
     - 첫 번째: 의도되지 않은 중복 호출 → "[주의] 중복 호출" 주석으로 명시
     - 두 번째: 실제 의도된 호출
     - 기능상 문제는 없으나 코드 리뷰 시 혼란을 줄 수 있으므로 주석으로 명확화함.

  2. ConversationManager.cs - userPrompt 플래그 타이밍
     - Unity 코루틴은 단일 스레드. yield return 시점에만 다른 코드가 실행됨.
     - userPrompt = true 설정: onUserPrompt_Next() 호출 시
     - userPrompt = false 소비: WaitForUserInput, BuildDialogue, LINE_RunCommands,
       WaitForDialogueSegmentSignalToBeTriggered(WC/WA) 각각에서 처리 후 초기화

  3. AutoReader.cs - timeStarted 보정 로직
     - 텍스트 출력(isBuilding) 시간이 읽기 대기 시간에서 차감됨.
     - 보정을 제거하면 짧은 대사도 MIN_READ_TIME(1초) 이상 대기하게 됨.

  4. DialogueContinuePrompt.cs - ForceMeshUpdate() 필요성
     - TMP는 텍스트 변경 후 즉시 textInfo를 갱신하지 않음.
     - Show() 호출 전 ForceMeshUpdate()로 강제 갱신해야 좌표가 정확함.

  5. DL_Dialogue_Data.cs - 기존 한국어 주석 보존
     - StartSignal.N 추가 관련 기존 주석 2개 보존 및 블록 주석으로 보강.

  6. DL_SPEAKER_DATA.cs - 기존 XML summary 보존
     - displayname 프로퍼티의 XML summary 보존 및 한국어 인라인 주석 보강.
