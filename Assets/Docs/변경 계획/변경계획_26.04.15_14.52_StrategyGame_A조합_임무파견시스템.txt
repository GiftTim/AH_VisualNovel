b. 요구한 기능
================================================================

  [ A 조합 = ① 경로탐색 + ③ 유틸리티 + ⑤ 캐릭터 + ⑥ 임무(파견) + ④ 길드 ]

  ①③⑤④는 B+C 조합으로 이미 완료됨.
  A 조합에서 새롭게 추가되는 유일한 시스템은:

    ⑥ 임무(파견) 시스템
    ─────────────────────────────────────────────────────────
    - 하루 동안 시간에 따라 임무가 랜덤하게 등장한다.
    - 플레이어(또는 외부 호출자)가 팀을 배정해 임무를 수락할 수 있다.
    - 수락된 임무는 팀이 이동 → 수행 → 귀환하는 흐름을 따른다.
    - 임무 수행 중 50% 지점에서 랜덤 이벤트가 발생할 수 있다.
    - 제한 시간(TimeToAccept) 내에 수락되지 않은 임무는 소멸(Lost)된다.
    - 하루의 모든 임무가 완료(Claimed) 또는 소멸(Lost)되면 하루 종료.
    - 임무 결과(성공/실패/미스)는 DayReport를 통해 Guild 경험치에 반영된다.
    ─────────────────────────────────────────────────────────

  [ 완료 기준 ]
  - 씬 실행 시 컴파일 에러 0
  - DayManager.StartDay() 호출 → 임무 등장 → 하루 종료 흐름 정상 동작
  - DayReport에 임무 통계(수락/성공/실패/미스) 누적
  - Guild.HandleDayReport()로 경험치 계산 정상 동작

  ─────────────────────────────────────────────────────────────
  STEP 1. DayMissionManager.cs 신규 생성
  ─────────────────────────────────────────────────────────────

  경로: Assets/Scripts/StrategyGame/Core/Mission/DayMissionManager.cs

  역할:
    하루 동안 임무 생성·배분·추적을 담당하는 MonoBehaviour.
    DayManager의 지시를 받으며 MissionUnit 인스턴스를 생성·관리한다.

  필수 공개 인터페이스 (DayManager가 호출):
    void Init(List<MissionSO> missionSOs, int missionAmount,
              float dayDuration,
              Action<List<MissionUnit>> newMissionsCallback)
      → 하루 시작 시 호출.
        missionSOs에서 missionAmount 개를 선택해 등장 시간(spawnTime)을
        dayDuration 범위 내에 고르게 배분한다.
        생성된 MissionUnit 목록을 내부에 보관한다.

    void UpdateMissions(float elapsedTime)
      → DayLoopCoroutine에서 0.5초마다 호출.
        각 MissionUnit.UpdateMission(elapsedTime)을 호출한다.
        spawnTime에 도달한 임무는 _activeMissions로 이동시키고
        newMissionsCallback을 통해 DayManager에 알린다.

    bool HasMissions()
      → 아직 처리되지 않은 임무(Claimed/Lost가 아닌 상태)가
        하나라도 남아있으면 true, 전부 끝나면 false.
        DayLoopCoroutine의 루프 종료 조건에 사용된다.

  필수 이벤트:
    UnityEvent<MissionUnit> OnMissionMiss
      → MissionUnit이 Lost 상태가 됐을 때 발행.
        DayManager.HandleMissionMiss()가 구독한다.

  내부 구조:
    private List<(MissionUnit mission, float spawnTime)> _pendingMissions;
      → Init()에서 생성된 전체 임무와 등장 예정 시간 목록

    private List<MissionUnit> _activeMissions;
      → 이미 등장해 처리 대기 중이거나 수행 중인 임무 목록

    private Action<List<MissionUnit>> _newMissionsCallback;
      → 새 임무가 등장할 때 DayManager에게 알리는 콜백

  STEP 2. DayManager.cs 수정 (주석 복원)
  ─────────────────────────────────────────────────────────────

  경로: Assets/Scripts/StrategyGame/Core/Day/DayManager.cs

  2-1. 필드 복원
    [SerializeField] private DayMissionManager _missionManager;  ← 주석 해제

  2-2. 이벤트 복원
    public UnityEvent<List<MissionUnit>> OnMissionAvailable;     ← 주석 해제

  2-3. Start() 복원
    _missionManager.OnMissionMiss.AddListener(HandleMissionMiss); ← 주석 해제

  2-4. StartDay() 복원
    var missionAmount = daySO.UseAllMissions
        ? daySO.MissionSOs.Count : daySO.MissionAmount;           ← 주석 해제
    _missionManager.Init(daySO.MissionSOs, missionAmount,
        daySO.DayDurationInSeconds, HandleNewMissions);           ← 주석 해제

  2-5. DayLoopCoroutine() 수정
    변경 전:
      while (_elapseTime < dayDuration)

    변경 후:
      while (_missionManager.HasMissions())

    주석 해제:
      _missionManager.UpdateMissions(_elapseTime);               ← 주석 해제

    ※ dayDuration 파라미터는 DayMissionManager.Init()에 전달되므로
      루프 조건에서 제거해도 무관하다.
      DaySO.DayDurationInSeconds는 임무 등장 시간 배분 범위로만 사용된다.

  2-6. 메서드 복원 (주석 블록 해제)

    public void ClaimMission(MissionUnit missionUnit, bool isSuccess)
    {
        _dayCharacterManager.HandleTeamCompleteMission(
            missionUnit, missionUnit.Team, isSuccess, CurrentTime);

        if (isSuccess)
            _dayReport.HandleMissionSucceded(missionUnit.Gold);
        else
            _dayReport.HandleMissionFailed();

        missionUnit.ClaimMission();
    }

    public void AcceptMission(MissionUnit mission, Team team)
    {
        _dayReport.HandleMissionAccepted(team.Members);
        _dayCharacterManager.HandleTeamAcceptMission(team);
        mission.AcceptMission(team);
    }

    public void StartMission(MissionUnit mission)
    {
        _dayCharacterManager.HandleTeamStartMission(mission.Team);
        mission.StartMission(CurrentTime);
    }

    private void HandleMissionMiss(MissionUnit missionUnit)
    {
        _dayReport.HandleMissionMiss();
    }

    private void HandleNewMissions(List<MissionUnit> newMissions)
    {
        _dayReport.AddCalls(newMissions.Count);
        OnMissionAvailable?.Invoke(newMissions);
    }

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  [ 검토한 방법들 ]

  방법 1: DayMissionManager 없이 DayManager에 직접 임무 로직 통합
  ──────────────────────────────────────────────────────────────
  - DayManager 하나에 임무 생성·배분·추적 로직을 모두 넣는다.
  - 단점: SRP(단일 책임 원칙) 위반. 이미 하루 사이클 제어 역할을 하는
          DayManager가 임무 관리까지 담당하면 클래스가 지나치게 커진다.
          레포 원본 설계와도 다르다 → 추후 View 통합 시 구조 불일치 발생.
  → ❌ 채택 안 함

  방법 2: DayMissionManager를 단순 데이터 클래스로 구현 (MonoBehaviour 아님)
  ─────────────────────────────────────────────────────────────────────────
  - MonoBehaviour 없이 순수 C# 클래스로 구현.
  - 단점: 원본 레포가 MonoBehaviour 기반으로 설계되어 있어 씬에 배치하는
          패턴을 따르는 것이 유리하다. 향후 Gizmo 디버깅이나 Inspector 연결도
          MonoBehaviour가 편리하다.
  → ❌ 채택 안 함

  방법 3: 레포 원본 DayMissionManager 그대로 복사 + 최소 수정 (채택) ✅
  ────────────────────────────────────────────────────────────────────
  - GameDispatchLike의 DayMissionManager.cs를 기반으로 설계하되,
    현재 프로젝트에 맞게 필요한 최소 수정만 적용한다.
  - 장점: 원본 레포 의도를 유지하며 Phase 8 계획과 정확히 일치한다.
          DayManager의 주석 처리된 인터페이스(Init, UpdateMissions,
          HasMissions, OnMissionMiss)를 그대로 활성화할 수 있다.
  → ✅ 채택

  [ DayLoopCoroutine 루프 조건 교체 이유 ]

  현재 (Phase C):
    while (_elapseTime < dayDuration)
    → 시간이 다 되면 하루 종료.
    → 임무가 있어도 시간이 끝나면 강제 종료.

  Phase 8 (채택):
    while (_missionManager.HasMissions())
    → 등장한 모든 임무가 Claimed 또는 Lost 될 때까지 하루가 계속된다.
    → 임무 수락 시간(TimeToAccept)이 끝나지 않은 임무가 있으면 대기한다.
    → 하루 길이(DayDurationInSeconds)는 임무 등장 시간 배분에만 사용된다.
    → 게임 흐름 상 더 자연스럽다.
    → 레포 원본 설계 의도와 일치한다.

h. 주의할 점
================================================================

  ① DayLoopCoroutine 루프 조건 교체 시 dayDuration 파라미터 처리
  ──────────────────────────────────────────────────────────────
  변경 전 루프는 dayDuration을 직접 비교했다.
  변경 후 루프는 _missionManager.HasMissions()를 사용하므로
  dayDuration 지역변수가 루프 밖에서 쓰이지 않는다.
  컴파일 경고(CS0219: unused variable)가 발생할 수 있다.
  → 해결: dayDuration 지역변수를 삭제하거나
          _missionManager.Init() 호출부에 인라인으로 직접 전달한다.

  ② DayMissionManager.HasMissions() 구현 시 무한루프 주의
  ──────────────────────────────────────────────────────────
  HasMissions()가 항상 true를 반환하면 DayLoopCoroutine이 절대 끝나지 않는다.
  구현 시 반드시 아래 조건으로 false 반환 케이스를 확보해야 한다:
    _pendingMissions가 비어있음 (등장 예정 없음)
    AND _activeMissions 전부 IsMissionClaimed() || IsMissionLost() == true
  초기 테스트 시 missionAmount = 1, TimeToAccept = 5 등
  짧은 값으로 빠른 종료를 확인하는 것을 권장한다.

  ③ StartDay() 호출 전 GameManager.NewGame() 또는 LoadSave() 선행 필요
  ──────────────────────────────────────────────────────────────────────
  DayManager.StartDay()는 내부에서
    _gameState = GameManager.Instance.GameState;
  를 호출한다.
  GameManager.NewGame() 또는 LoadSave()가 먼저 호출되지 않으면
  _gameState가 null이어서 NullReferenceException이 발생한다.
  → 씬 시작 시 자동 실행(디버그)을 원한다면 GameManager.Start()에서
    NewGame()을 호출하거나 별도 디버그 스크립트를 추가한다.

  ④ DayMissionManager Init() 에서 missionSOs가 비어있을 경우 처리
  ──────────────────────────────────────────────────────────────
  Day_Default.asset의 MissionSOs가 비어있으면 Init()에 빈 리스트가 전달된다.
  이 경우 _pendingMissions도 비어 HasMissions()가 즉시 false를 반환,
  하루가 시작 직후 종료된다.
  → PHASE 8-3에서 반드시 MissionSO 인스턴스를 Day_Default.asset에 연결한다.

  ⑤ 각 Phase 완료 후 반드시 컴파일 확인
  ──────────────────────────────────────
  PHASE 8-1(DayMissionManager 생성) 완료 후 컴파일 확인.
  PHASE 8-2(DayManager 복원) 완료 후 컴파일 확인.
  에러가 남은 상태에서 씬을 저장하거나 Unity를 종료하면 씬 파일이 손상될 수 있다.

  ⑥ 씬 수정 전 git commit 권장
  ──────────────────────────────
  PHASE 8-1, 8-2 완료 후(스크립트 수정 완료) 한 번 commit한다.
  PHASE 8-4 씬 수정 완료 후 다시 한 번 commit한다.
  각 Phase별로 되돌릴 수 있는 체크포인트를 확보한다.

  ⑦ MissionUnit.Gold 프로퍼티 버그 (원본 레포 버그 그대로 유지)
  ──────────────────────────────────────────────────────────────

    public int Gold => _missionSO.RewardExperience;  // ← 원본 버그: RewardGold가 아님
