c. 변경 후 작동 흐름
================================================================================

  논리 라인 처리 전체 흐름 (주석으로 각 단계를 설명함):

  1. ConversationManager.RunningConversation()
     └─ logicalLineManager.TryGetLogic(line, out logic)
           └─ LogicalLineManager: logicalLines를 순회하며 Matches()가 true인 핸들러 탐색

  2. 핸들러 별 Execute() 흐름

     [LL_Input]
       InputPanel.Show(title)
       → isWaitingOnUserInput == false 될 때까지 yield return null
       → 완료 후 대화 계속 진행

     [LL_Operator]
       rawLine을 REGEX_ARITHMATIC으로 Split
       → 변수명 / 연산자 / 우변 수식 분리
       → CalculateValue()로 우변 계산
       → ProcessOperator()로 VariableStore에 적용

     [LL_Condition]
       if(조건) 에서 조건 문자열 추출
       → EvaluateCondition()으로 true/false 판정
       → RipEncapsulationData()로 if/else 블록 추출
       → SetProgress()로 전체 블록 건너뛰기
       → 조건에 맞는 블록을 EnqueuePriority로 우선 실행

     [LL_Choice]
       RipEncapsulationData()로 choice { } 블록 추출
       → GetChoicesFromData()로 '-' 기준 Choice 목록 파싱
       → ChoicePanel.Show() → 사용자 선택 대기
       → 선택된 Choice.resultLines로 새 Conversation 생성
       → SetProgress()로 choice 블록 건너뛰기
       → EnqueuePriority로 결과 우선 실행

  3. VariableStore (모든 LL에서 접근)
     $변수명 또는 $db.변수명 형태로 접근
     CreateVariable → TryGetValue / TrySetValue → HasVariable / RemoveVariable


================================================================================
d. 주의할 점
================================================================================

  1. 코드 로직 변경 없음
     - 주석만 추가. 변수명, 메서드 시그니처, 실행 순서 모두 유지.

  2. LogicalLineUtils.cs - 나눗셈 버그 (기존 코드 그대로 유지)
     - CalculateValue_DivisionAndMultiplication()의 이중 중첩 if(rightOperand == 0)로
       나눗셈 결과 저장 코드가 절대 실행되지 않음.
     - "[주의] 이중 중첩 버그" 주석으로 명시했으나 코드는 변경하지 않음.
     - 수정이 필요하면 별도 변경 계획 수립 필요.

  3. LogicalLineUtils.cs - operands.Remove(i + 1) 잠재적 문제 (기존 코드 그대로 유지)
     - List<object>.Remove(value)는 값 기준 제거이므로
       RemoveAt(index)와 다르게 동작할 수 있음.
     - "[주의] Remove(value)" 주석으로 명시했으나 코드는 변경하지 않음.

  4. LL_Operator.cs - keyword NotImplementedException
     - 런타임에서 keyword 프로퍼티에 직접 접근하지 않으므로 게임 중 에러 없음.
     - 하지만 LogicalLineManager가 향후 keyword를 직접 참조하도록 변경되면 에러 발생.
     - 주석으로 이 의도와 위험을 명시함.

  5. LL_Choice.cs - autoReader 미사용 변수
     - Execute() 내에서 선언만 되고 사용되지 않음.
     - "향후 확장용" 인라인 주석 추가. 코드는 변경하지 않음.

  6. LL_Condition.cs - 인덱스 오프셋 (startingIndex += 2, endingIndex -= 1)
     - 헤더 줄과 { } 줄을 제외하기 위한 오프셋.
     - 이 값을 임의로 변경하면 잘못된 줄이 실행될 수 있음.
     - 주석에서 각 오프셋의 의미를 명확히 설명함.

  7. 기존 한국어/영어 혼용 주석 보존
     - LogicalLineUtils, LL_Operator 등에 있는 기존 주석은 삭제 없이 보강함.
