4. 방식 선택 근거 (e)
================================================================

[MissionDispatcher 별도 클래스로 분리]

  대안 1: MissionDispatcher 신규 생성 (채택)
    → 파견 로직(활성화 + 이동 + 비활성화)을 한 곳에서 관리.
    → TestingSpotState → MissionDispatcher로 위임 구조 유지.
    → 나중에 UI 버튼이 MissionDispatcher.Dispatch()를 호출하는 것으로
      자연스럽게 교체 가능. TestingSpotState는 버려도 됨.

  대안 2: TestingSpotState에 직접 추가
    → 코드가 단순하지만 테스트 클래스에 실제 로직이 누적됨.
    → 나중에 UI로 교체할 때 로직을 다시 옮겨야 함.

  대안 3: CharacterAgent에 SetActive 처리 포함
    → CharacterAgent는 "이동"만 담당해야 함.
    → 활성/비활성은 파견 로직에서 결정하는 것이 적합.

[onArrived 콜백으로 SetActive(false) 처리]

  - CharacterAgent.MoveAlong()의 onArrived 콜백이 이미 존재.
  - 도착 시 실행할 동작을 외부에서 주입하므로
    CharacterAgent 내부 코드 변경 없이 처리 가능.

[신규: MissionDispatcher.cs]
  경로: Assets/Scripts/StrategyGame/Core/MissionDispatcher.cs

  public class MissionDispatcher : MonoBehaviour
  {
      [SerializeField] LineConnectorManager _connector;
      [SerializeField] Transform _hqTransform;   // HQ Spot의 Transform
      [SerializeField] CharacterAgent _character; // 초기 위치 세팅 대상

      void Awake()
      {
          // 캐릭터 시작 위치를 HQ로 설정 후 비활성화
          _character.transform.position = _hqTransform.position;
          _character.gameObject.SetActive(false);
      }

      // 파견: 캐릭터를 HQ에서 목표 건물로 이동 → 도착 시 비활성화
      public void Dispatch(CharacterAgent character, Spot targetSpot)
      {
          targetSpot.SetState(BuildingState.Selected);
          character.gameObject.SetActive(true);
          Transform[] path = _connector.GetWaypoints(targetSpot);
          if (path != null)
              character.MoveAlong(path, () => character.gameObject.SetActive(false));
      }

      // 귀환: 캐릭터를 목표 건물에서 HQ로 이동 → 도착 시 비활성화
      public void Return(CharacterAgent character, Spot fromSpot)
      {
          fromSpot.SetState(BuildingState.Completed);
          character.gameObject.SetActive(true);
          Transform[] path = _connector.GetReturnWaypoints(fromSpot);
          if (path != null)
              character.MoveAlong(path, () => character.gameObject.SetActive(false));
      }
  }

7. 주의할 점 (h)
================================================================

  1. 캐릭터 초기 위치
     - Awake()에서 _hqTransform.position으로 강제 이동 후 SetActive(false).
     - 씬에서 캐릭터 위치를 수동으로 맞출 필요 없음.
     - _hqTransform에 HQ Spot 오브젝트가 연결되어 있어야 함.

  2. 도착 후 SetActive(false) 타이밍
     - onArrived 콜백은 MoveCoroutine 마지막에 실행됨.
     - SetActive(false) 직전에 OnArrived UnityEvent도 실행되므로
       이벤트 리스너가 있다면 순서 주의.

  3. 이동 중 재파견 요청
     - 이동 중 Dispatch()가 다시 호출되면 CharacterAgent.MoveAlong()이
       기존 코루틴을 StopCoroutine 후 새 경로로 재이동함.
     - 재파견을 막으려면 MissionDispatcher 내부에 이동 중 여부 플래그 추가 필요.
       (현재 계획 범위 밖)

  4. B 키 귀환 이동과의 관계
     - 귀환도 MissionDispatcher.Return()을 통해 처리.
     - 귀환 도착(HQ) 시 동일하게 SetActive(false) 처리됨.
     - Return() 호출 시 캐릭터가 현재 목표 건물 위치 근처에 있어야 자연스러움.
       (A 키 파견 후 도착 비활성화된 위치가 목표 건물이므로 정상 동작)

  5. 캐릭터 선택 UI 연결 (추후)
     - 현재는 TestingSpotState에서 직접 _character를 지정.
     - UI 선택 시스템 구현 후 MissionDispatcher.Dispatch()를 호출하는
       주체만 교체하면 됨. Dispatch() 시그니처는 변경 불필요.
