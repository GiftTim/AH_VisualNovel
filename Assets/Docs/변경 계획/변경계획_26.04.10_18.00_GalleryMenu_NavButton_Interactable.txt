b. 요구한 기능
================================================================

  [현재 동작]
    - previousButton / nextButton을 사용할 수 없는 상황에서
      gameObject.SetActive(false)로 버튼을 아예 숨김

  [원하는 동작]
    - 버튼을 숨기지 않고 항상 계층에 존재하도록 유지
    - 사용할 수 없을 때: button.interactable = false
    - 사용할 수 있을 때: button.interactable = true

  [이유]
    - 버튼이 사라지면 NavBar 레이아웃이 흔들릴 수 있음
    - UI 상 항상 버튼 자리가 보이는 것이 의도된 디자인

c. 현재 상황 및 코드
================================================================

  [ UpdateNavBarWindow() - 현재 ]

    private void UpdateNavBarWindow()
    {
        for (int i = 0; i < pageButtons.Count; i++)
        {
            int page = windowStart + i;
            pageButtons[i].onClick.RemoveAllListeners();
            pageButtons[i].onClick.AddListener(() => LoadPage(page));
            pageButtons[i].GetComponentInChildren<TextMeshProUGUI>().text = page.ToString();
            pageButtons[i].gameObject.SetActive(page <= maxPages);
        }
        previousButton.gameObject.SetActive(windowStart > 1);             ← SetActive 사용
        nextButton.gameObject.SetActive(windowStart + pageButtons.Count <= maxPages);  ← SetActive 사용
    }

  [ 문제 요약 ]
    - previousButton / nextButton이 SetActive(false)로 완전히 숨겨짐
    - 버튼이 Hierarchy에서 비활성화되어 레이아웃 공간을 차지하지 않음
    - 원하는 동작은 버튼은 보이되 클릭만 막는 것

================================================================
d. 요구한 기능을 만들기 위해서 어떤 식으로 생성하거나 변경해야 하는지
================================================================

  [핵심 메커니즘]
    UpdateNavBarWindow() 안의 previousButton / nextButton 처리 부분에서
    gameObject.SetActive() 대신 button.interactable 프로퍼티를 사용한다.

  [필요한 변경 - GalleryMenu.cs]

    UpdateNavBarWindow() 수정:

      변경 전:
        previousButton.gameObject.SetActive(windowStart > 1);
        nextButton.gameObject.SetActive(windowStart + pageButtons.Count <= maxPages);

      변경 후:
        previousButton.interactable = (windowStart > 1);
        nextButton.interactable = (windowStart + pageButtons.Count <= maxPages);

  [추가 고려사항]
    - pageButtons (페이지 번호 버튼들) 의 SetActive는 그대로 유지
      (존재하지 않는 페이지 번호 버튼은 숨기는 것이 맞음)
    - previousButton / nextButton 의 초기 상태:
      현재 ConstructNavBar에서 SetActive를 삭제한 상태이므로
      초기값은 Inspector 상의 상태를 따름.
      UpdateNavBarWindow()가 ConstructNavBar 마지막에 호출되므로
      interactable 값도 진입 시 자동 설정됨 → 별도 초기화 불필요

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

[ 방법 A (채택): button.interactable = true/false ]

  장점
  ✓ 버튼 GameObject가 Hierarchy에 남아 레이아웃 유지
  ✓ 코드 변경이 UpdateNavBarWindow() 2줄만으로 최소화
  ✓ Unity Button의 표준 비활성화 방식 (Disabled Color 자동 적용)
  ✓ 시각적으로 버튼이 흐릿하게 표시되어 사용 불가 상태 전달 가능

[ 방법 B: gameObject.SetActive(false) - 현재 방식 ]

  ✗ 버튼이 Hierarchy에서 제거되어 레이아웃이 변할 수 있음
  ✗ 요구 사항과 불일치

[ 방법 C: CanvasGroup alpha + blocksRaycasts ]

  ✓ 시각적 제어와 클릭 차단을 분리 가능
  ✗ 이 케이스에서는 과도한 복잡도
  ✗ 추가 컴포넌트 필요

  → 방법 A가 변경 범위 최소, 표준 Unity 패턴이므로 채택

f. 어떤 순서로 진행할 것인지
================================================================

  [코드 변경]
  1. UpdateNavBarWindow() 수정
       previousButton.gameObject.SetActive(...)
       → previousButton.interactable = (...)

       nextButton.gameObject.SetActive(...)
       → nextButton.interactable = (...)

  [테스트]
  2. Unity 실행 → 갤러리 진입
       - previousButton 비활성(interactable=false, Disabled Color) 확인
       - nextButton 활성(interactable=true) 확인 (총 페이지 > 3인 경우)
       - 두 버튼 모두 화면에 표시 확인

  3. nextButton 클릭
       - previousButton interactable=true 확인
       - 두 버튼 모두 화면에 표시 확인

  4. previousButton 클릭 (1번 윈도우 복귀)
       - previousButton interactable=false 확인

  5. 마지막 윈도우 이동 확인
       - nextButton interactable=false 확인
