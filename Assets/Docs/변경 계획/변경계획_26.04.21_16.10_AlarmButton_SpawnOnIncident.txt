b. 요구한 기능
================================================================

1. Spot의 BuildingState가 Incident가 되는 순간
   Assets/Resources/Prefab/[StrategyGame]UI/SGButton 프리팹을
   5-Player Interaction 패널 안에 동적으로 생성(Instantiate)한다.

   SGButton 프리팹 구성 (신규 제작):
     SGButton (Root)
       ├─ AlarmButton  (기존 프리팹 자식으로 배치)
       ├─ WorkButton   (기존 프리팹 자식으로 배치)
       └─ CheckButton  (기존 프리팹 자식으로 배치)

2. 생성된 SGButton의 위치는
   Incident가 된 Spot(TargetSpot) GameObject의 우측 상단(right top)에 맞춘다.
   - Pivot    : (1, 1)  — right top
   - Position : Spot의 RectTransform 우상단 모서리 위치
   - 부모     : 5-Player Interaction

3. AlarmButton에 붙을 새 스크립트 (AlarmTimer) 기능:
   - Slider의 value를 1에서 0까지 서서히 감소시킨다.
   - 감소 소요 시간은 Inspector에서 직접 입력 가능하다.
   - 타이머가 0에 도달해도 현재는 아무런 추가 효과 없음 (추후 추가 예정).

[ 신규 생성 ]

1. SGButton 프리팹  (Assets/Resources/Prefab/[StrategyGame]UI/)
   - Root(SGButton) 크기 : AlarmButton / WorkButton / CheckButton과 동일한 크기
   - 자식 3개(AlarmButton, WorkButton, CheckButton) 모두
     Anchor = Stretch (min 0,0 / max 1,1) 로 설정 → SGButton 영역을 가득 채움
   - 세 자식이 동일 영역에 겹쳐 쌓임
     → 상태에 따라 SetActive로 하나씩 전환하는 방식으로 활용 예정
   - Pivot (1, 1) — right top 기준으로 제작

2. AlarmTimer.cs  (Assets/Scripts/StrategyGame/Core/UI/)
   - AlarmButton 프리팹에 붙을 타이머 스크립트
   - [SerializeField] float  _duration — Inspector에서 시간(초) 입력
   - [SerializeField] Slider _slider   — AlarmButton의 Slider 참조
   - Start() 또는 공개 메서드에서 DOTween으로 Slider.value 1 → 0 감소
   - 타이머 만료 시 현재는 아무런 처리 없음 (추후 추가 예정)

3. AlarmSpawner.cs  (Assets/Scripts/StrategyGame/Core/UI/)
   - 각 Normal 타입 Spot GameObject에 붙이는 스크립트
   - [SerializeField] RectTransform _playerInteractionPanel — 5-Player Interaction
   - Spot의 OnStateChanged 이벤트 구독
       Incident 진입 : SGButton Instantiate → 위치 계산 → _playerInteractionPanel 자식으로 배치
       Incident 이탈 : 생성된 SGButton Destroy
   - 위치 계산:
       Spot의 RectTransform.GetWorldCorners()[2] (우상단 월드 좌표) 를 구한 뒤
       RectTransformUtility.WorldToScreenPoint() →
       RectTransformUtility.ScreenPointToLocalPointInRectangle()로
       _playerInteractionPanel의 로컬 좌표로 변환하여 anchoredPosition에 적용

[ 변경 ]

   - SetState() 안에서 OnStateChanged?.Invoke(state) 호출

[ 씬 Inspector 작업 ]

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

[ 대안 A ] Spot.cs 안에 SGButton 생성 로직 직접 추가
  장점 : 파일 수가 적고 구조가 단순
  단점 : Spot이 UI 스폰 책임까지 떠안아 단일 책임 원칙(SRP) 위반.
         나중에 버튼 구성이 바뀌면 Spot 수정 필요.

[ 대안 B ] MissionDispatcher.cs에서 Incident 설정과 함께 스폰
  장점 : 파견 흐름과 알람 생성이 같은 곳에 있어 추적 쉬움
  단점 : Incident는 Dispatcher 외부에서도 발생 가능 →
         MissionDispatcher를 경유하지 않는 케이스에서 SGButton이 생성되지 않음.

[ 채택 ] AlarmSpawner를 별도 컴포넌트로 분리
  이유 :
  - Spot의 상태 변화를 이벤트로 구독 → 발생 경로와 무관하게 항상 반응
  - Spot.cs는 상태 관리만, AlarmSpawner는 UI 스폰만 담당 → SRP 유지
  - 나중에 SGButton 외 다른 UI도 OnStateChanged를 구독해 확장 가능
  - Inspector 연결만으로 각 Spot에 독립적으로 적용 가능

h. 주의할 점
================================================================

1. SGButton 위치 계산 — 캔버스 좌표계
   Spot은 Canvas 안의 RectTransform.
   GetWorldCorners()[2]로 우상단 월드 좌표를 얻은 뒤
   RectTransformUtility.ScreenPointToLocalPointInRectangle()로
   5-Player Interaction 패널의 로컬 좌표로 변환해야 한다.
   월드 좌표를 그대로 anchoredPosition에 넣으면 위치가 어긋난다.

2. SGButton 중복 생성 방지
   같은 Spot에 Incident가 반복 호출되면 SGButton이 여러 개 생성될 수 있다.
   AlarmSpawner에서 현재 인스턴스 참조(_currentButton)를 보관하고
   생성 전 null 체크 후 이미 있으면 Destroy 후 재생성한다.

3. Slider DOTween — Slider.DOValue
   DOTween은 Slider.DOValue(0, duration)을 지원한다.
   DOTween UI 확장(DOTweenModuleUI)이 포함되어 있어야 하며,
   컴파일 오류 시 DOVirtual.Float으로 대체한다.

4. 타이머 만료 시 추가 처리 미구현
   AlarmTimer는 현재 value가 0에 도달해도 아무것도 하지 않는다.
   추후 기능 추가 시 OnTimerExpired 이벤트를 AlarmTimer에 추가하고
   외부에서 구독하는 방식으로 확장한다.

5. Sort Order
   SGButton이 5-Player Interaction 안에 생성될 때
   해당 패널의 Canvas Sort Order가 배경·건물·캐릭터보다 높아야
   버튼이 가려지지 않는다.

6. SGButton 자식 버튼 Stretch 설정
   AlarmButton, WorkButton, CheckButton 모두 Anchor = Stretch (0,0 / 1,1),
   offsetMin/offsetMax = (0,0) 으로 SGButton 전체를 채운다.
   세 자식이 동일 영역에 겹치므로 초기 상태는 AlarmButton만 활성,
   나머지는 SetActive(false)로 시작하는 것을 권장한다.
   (Incident 상태이므로 AlarmButton이 기본 표시)
