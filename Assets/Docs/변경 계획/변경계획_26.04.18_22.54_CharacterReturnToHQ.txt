3. 구현 방향 (d)
================================================================

  B 키 입력 시 아래 흐름으로 처리:

  ┌──────────────────────────────────────────────────────────────┐
  │  Step A. BuildingLineConnector.cs                            │
  │    → GetReturnWaypoints(Spot fromSpot) 메서드 추가           │
  │       GetWaypoints()의 반환 배열을 역순으로 뒤집어 반환      │
  │       반환 형식: Transform[] (targetSpot → waypoints → HQ)  │
  │                                                              │
  │  Step B. TestingSpotState.cs 수정                            │
  │    → B 키 입력 시:                                           │
  │       1) _targetSpot.SetState(Completed)                     │
  │       2) Transform[] path = _connector                       │
  │                             .GetReturnWaypoints(_targetSpot) │
  │       3) _character.MoveAlong(path)                          │
  └──────────────────────────────────────────────────────────────┘

  [전체 흐름]

    [TestingSpotState]
      B 키 입력
        ↓
    _targetSpot.SetState(Completed)
        ↓
    _connector.GetReturnWaypoints(_targetSpot)
        → 해당 Spot의 RoadPath 검색
        → GetWaypoints()와 동일하게 경로 구성 후 Array.Reverse
        → [targetSpot, ..., waypoint0, HQ] 반환
        ↓
    _character.MoveAlong(path)
        → 코루틴으로 path 순서대로 Lerp 이동 (targetSpot → HQ)
        → 도착 시 OnArrived 이벤트 발생

4. 방식 선택 근거 (e)
================================================================

[역방향 경로 처리]

  대안 1: BuildingLineConnector에 GetReturnWaypoints() 추가 (채택)
    → GetWaypoints()와 대칭된 메서드로 역할이 명확.
    → TestingSpotState는 "어떤 경로인지" 신경 쓰지 않아도 됨.
    → 나중에 MissionManager로 이관할 때도 메서드 호출만 바꾸면 됨.

  대안 2: TestingSpotState에서 Array.Reverse 직접 처리
    → 코드가 단순하지만 경로 구성 책임이 TestingSpotState에 섞임.
    → 테스트 클래스에 경로 조작 로직이 들어가는 것은 부적절.

  대안 3: CharacterAgent에 MoveAlongReverse() 추가
    → CharacterAgent는 "이동"만 담당해야 하므로 경로 방향 결정은 밖에서 처리하는 것이 적합.
    → 경로 배열의 역순은 이미 MoveAlong()으로 처리 가능하므로 중복.

[트리거 방식]

  현재와 동일하게 TestingSpotState의 B 키에서 직접 처리.
  Mission 시스템 도입 전 임시 구조이므로 단순하게 유지.

7. 주의할 점 (h)
================================================================

  1. A 키로 이동 완료 전에 B 키를 누르는 경우
     - CharacterAgent.MoveAlong()은 기존 코루틴을 중단하고 새 경로로 재이동.
     - 즉, 이동 도중 B를 누르면 중간 위치에서 바로 귀환 시작.
     - 이 동작이 의도와 맞는지 확인. 원하지 않으면 MoveAlong() 내부에서
       이동 중일 때 새 요청을 무시하는 처리 추가 고려.

  2. 캐릭터가 targetSpot에 도착하지 않은 상태에서 B 키 입력
     - 위 1번과 동일. 캐릭터 위치가 targetSpot이 아닌 중간 지점에서 귀환 시작.

  3. GetReturnWaypoints()는 GetWaypoints()를 호출 후 Reverse
     - GetWaypoints()가 null을 반환하면 GetReturnWaypoints()도 null 반환.
     - TestingSpotState에서 null 체크 처리됨 (path != null 조건).

  4. Array.Reverse는 원본 배열을 직접 수정
     - GetWaypoints()에서 new로 생성한 배열을 반환하므로 원본 데이터 영향 없음.
     - _roads의 waypoints 배열은 건드리지 않음.

  5. 나중에 Mission 시스템으로 이관 시
     - TestingSpotState의 B 키 로직
       (SetState(Completed) + GetReturnWaypoints + MoveAlong)을
       MissionManager 또는 QuestCoordinator로 이전하면 됨.
