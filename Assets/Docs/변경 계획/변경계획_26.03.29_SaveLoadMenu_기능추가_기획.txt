====================================================
  SaveLoadMenu 기능 추가 기획서
  작성일: 2026-03-29
====================================================

[ 추가할 기능 3가지 ]
  1. OpenSavePage()로 SaveAndLoadMenu에 들어가서 saveButton이 SetActive(true)가 된 상태의
  버튼을 누르면 사라지고 대신해서 loadButton 이 SetActive가 되도록 상태로 전환.
  2.  OpenSavePage()로 SaveAndLoadMenu에 들어가서 1.번으로 loadButton이 SetActive(true)가
  데이터가 있는 슬롯 클릭할 경우 → 덮어쓰기 저장이 되도록
  3. OpenLoadPage()로 SaveAndLoadMenu에 들어가서데이터가 있는 슬롯 클릭 → 불러오기


----------------------------------------------------
a. 어떤 식으로 추가/변경할 것인지
----------------------------------------------------

[ 기능 1 - saveButton 클릭 시 loadButton으로 전환 ]

  현재 상태:
    - OpenSavePage()로 진입 시 saveButton이 계속 유지된 채로 남아 있음
    - Save() 메서드 내부에서 PopulateDetailsFromFile()을 이미 호출하고 있음
      → Save() 안에서 직접 SetActive로 버튼을 바꿔도
        PopulateDetailsFromFile()가 바로 덮어쓰기 때문에 효과 없음

  변경 내용:
    - Save() 내부에서 버튼을 직접 SetActive로 전환하지 않음
    - 대신 PopulateDetailsFromFile() 내부의 file != null 분기 로직을 수정
        → 파일이 존재하면 Save 모드에서도 loadButton을 활성화

    수정 대상: PopulateDetailsFromFile() 내 file != null 블록 (line 64~65)

    기존:
        loadButton.gameObject.SetActive(function == MenuFunction.load);
        saveButton.gameObject.SetActive(function == MenuFunction.save);

    변경:
        loadButton.gameObject.SetActive(true);  // 파일 있으면 항상 Load 가능
        saveButton.gameObject.SetActive(function == SaveAndLoadMenu.MenuFunction.save);

    효과:
        상태                      결과
        Save 모드 + 빈 슬롯       Save 버튼만
        Save 모드 + 저장된 슬롯   Save + Load 둘 다
        Load 모드                 Load + Delete

    - Save() 호출 → PopulateDetailsFromFile() 호출 → 파일이 생겼으므로 file != null 경로
      → loadButton 자동 활성화. 별도 SetActive 코드 불필요


[ 기능 2 - Save 모드에서 loadButton이 활성화된 슬롯 클릭 시 덮어쓰기 저장 ]

  현재 상태:
    - SaveLoadSlot.Save() 메서드 이미 존재
        → activeFile의 slotNumber를 세팅하고 Save() 호출 후 슬롯 갱신
    - 기능 1의 수정으로 인해 저장 후 자동으로 Load 버튼이 표시됨

  변경 내용:
    - 인스펙터에서 saveButton.onClick → SaveLoadSlot.Save() 연결 확인/설정
    - Save() 내부 코드 변경 없음 (기능 1의 PopulateDetailsFromFile 수정으로 처리됨)


[ 기능 3 - Load 모드에서 슬롯 클릭 시 불러오기 ]

  현재 상태:
    - SaveLoadSlot.Load() 메서드 이미 존재
        → filePath로 VNGameSave.Load(filePath, true) 호출 후 메뉴 닫기
    - file != null일 때 loadButton이 load 모드에서 표시되도록 이미 처리됨 (line 64)

  변경 내용:
    - 인스펙터에서 loadButton.onClick → SaveLoadSlot.Load() 연결 확인/설정
    - 코드 변경 없음, 인스펙터 연결만 필요
    - SaveAndLoadMenu.Close(closeAllMenus: true)가 정상 동작하는지 확인 필요


[ 기존 미완성 부분 - deleteButton ]

  - file != null 블록에 deleteButton.SetActive 누락
  - deleteButton은 load 모드에서만 등장해야 함
  → file != null 블록에 아래 한 줄 추가:
      deleteButton.gameObject.SetActive(function == SaveAndLoadMenu.MenuFunction.load);


----------------------------------------------------
b. 다른 방법들과 비교
----------------------------------------------------

[ 기능 1 - Save 후 버튼 전환 방식 비교 ]

  방법 A (기각): Save() 실행 후 해당 슬롯의 버튼을 직접 SetActive로 전환
    - 장점: 코드 변경 최소화처럼 보임
    - 단점: Save() 내부에 이미 PopulateDetailsFromFile() 호출이 있어
            어느 위치에 넣어도 덮어씌워지거나 두 개의 상태 관리 경로가 생겨 충돌

  방법 B (채택): PopulateDetailsFromFile() 로직 자체를 수정
    - 장점: 버튼 상태 결정이 Populate 하나로 통일됨. 구조 일관성 유지.
            Save() 이후 자동으로 올바른 버튼 상태가 반영됨
    - 단점: 없음

  방법 C: VNMenuManager에서 모드 전환 처리 (메뉴를 닫고 다시 열기)
    - 장점: 외부에서 제어 가능
    - 단점: 메뉴 닫기/열기 애니메이션이 재생되어 UX가 어색함

  → 방법 B 채택. 버튼 상태는 Populate 하나에서 결정하는 구조가 일관성 있고 안전함


[ 기능 2, 3 - 슬롯 클릭 처리 방식 비교 ]

  방법 A (채택): Save() / Load() 메서드를 인스펙터 onClick에 직접 연결
    - 장점: 이미 메서드가 구현되어 있어 추가 코드 불필요
    - 단점: 인스펙터 설정을 놓치기 쉬움

  방법 B: SaveAndLoadMenu에서 슬롯 클릭 이벤트를 중앙 관리
    - 장점: 이벤트 흐름이 한 곳에서 관리됨
    - 단점: 현재 구조에서는 오히려 코드가 복잡해짐

  → 방법 A 채택. 이미 구현된 메서드를 활용하는 것이 최선


----------------------------------------------------
c. 진행 순서
----------------------------------------------------

  Step 1. deleteButton 누락 처리 (코드)
    - SaveLoadSlot.cs의 file != null 블록에 deleteButton.SetActive 한 줄 추가

  Step 2. PopulateDetailsFromFile() 수정 (코드)
    - file != null 블록의 loadButton / saveButton SetActive 로직 수정:
        loadButton.gameObject.SetActive(true);
        saveButton.gameObject.SetActive(function == SaveAndLoadMenu.MenuFunction.save);

  Step 3. saveButton / loadButton 인스펙터 연결 확인 (Unity 에디터)
    - 각 SaveLoadSlot 프리팹/오브젝트에서
        saveButton.onClick → Save()
        loadButton.onClick → Load()
        deleteButton.onClick → Delete()  (추후 Delete 구현 시)

  Step 4. 테스트
    - Save 모드 진입 → 빈 슬롯 저장 후 loadButton으로 전환 확인
    - Save 모드 진입 → 기존 슬롯 덮어쓰기 후 loadButton으로 전환 확인
    - Load 모드 진입 → 슬롯 불러오기 후 메뉴 닫힘 확인
    - 저장한 슬롯만 전환되고 나머지 슬롯은 영향 없는지 확인
    - AutoSlot이 전환 로직과 무관한지 확인
