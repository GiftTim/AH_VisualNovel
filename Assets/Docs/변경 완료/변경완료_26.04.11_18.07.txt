2. 변경 내역
================================================================

----------------------------------------------------------------
[변경 1] ConfigMenu.cs — SetDisplayResolution() 파싱 로직
----------------------------------------------------------------

  Before (Line ~142):
    string resolution = ui.resolutions.captionText.text;
    string[] values = resolution.Split('x');

  After:
    string rawText = ui.resolutions.captionText.text;
    string resolution = ExtractResolution(rawText);
    string[] values = resolution.Split('x');

  이유:
    captionText.text = "창모드 (1920 x 1080)"을 바로 Split('x') 하면
    values[0] = "창모드 (1920 " 으로 파싱 실패.
    ExtractResolution()으로 괄호 안 "1920 x 1080"만 추출한 뒤 Split하면
    values[0] = "1920", values[1] = " 1080" → 정상 파싱.


----------------------------------------------------------------
[변경 2] ConfigMenu.cs — SetDisplayResolution() 저장 로직
----------------------------------------------------------------

  Before (Line ~155):
    config.display_resolution = ExtractResolution(ui.resolutions.captionText.text);

  After:
    config.display_resolution = ui.resolutions.captionText.text;

  이유:
    ExtractResolution() 래핑 시 "전체창 (1920 x 1080)" → "1920 x 1080" 으로
    모드 정보가 소실됨. 전체 텍스트를 저장해야 Load()에서 정확히 복원 가능.


----------------------------------------------------------------
[변경 3] VN_Configuration.cs — display_resolution 기본값
----------------------------------------------------------------

  Before (Line 14):
    public string display_resolution = "1920 x 1080";

  After:
    public string display_resolution = "전체창 (1920 x 1080)";

  이유:
    기본값도 옵션 전체 텍스트 형식으로 맞춰야 Load()의 직접 비교가 동작.


----------------------------------------------------------------
[변경 4] VN_Configuration.cs — Load() 비교 로직
----------------------------------------------------------------

  Before (Line ~39-42):
    string optionText = ui.resolutions.options[i].text;
    string optionResolution = ConfigMenu.ExtractResolution(optionText);
    if(optionResolution == display_resolution)

  After:
    string optionText = ui.resolutions.options[i].text;
    if(optionText == display_resolution)

  이유:
    display_resolution에 전체 텍스트("전체창 (1920 x 1080)")가 저장되므로
    ExtractResolution() 없이 optionText와 직접 비교.

3. 변경 후 동작 흐름
================================================================

  [저장 흐름]
  1. 사용자가 Dropdown에서 옵션 선택 (예: "창모드 (1280 x 720)")
  2. SetDisplayResolution() 호출
  3. index != 0 → rawText = "창모드 (1280 x 720)"
  4. ExtractResolution(rawText) → "1280 x 720"
  5. Split('x') → values[0]="1280", values[1]=" 720"
  6. Screen.SetResolution(1280, 720, FullScreenMode.Windowed) 즉시 적용
  7. config.display_resolution = "창모드 (1280 x 720)" (전체 텍스트 저장)
  8. OnApplicationQuit() → vnconfig.cfg에 저장

  [복원 흐름]
  1. 앱 실행 → LoadConfig() → VN_Configuration.Load()
  2. 루프: ui.resolutions.options 순회
     - optionText = "전체창 (1920 x 1080)" != "창모드 (1280 x 720)" → skip
     - optionText = "창모드 (1920 x 1080)" != "창모드 (1280 x 720)" → skip
     - optionText = "창모드 (1600 x 900)" != "창모드 (1280 x 720)" → skip
     - optionText = "창모드 (1280 x 720)" == "창모드 (1280 x 720)" → res_index = 3, break
  3. ui.resolutions.value = 3
  4. SetDisplayResolution() → "창모드 (1280 x 720)" 정확히 복원

  [폴백]
  기존 cfg에 "1920 x 1080" (구 형식) 저장된 경우
  → 어떤 optionText와도 불일치 → res_index = 0 (전체창) 폴백.
  첫 실행이나 구버전 cfg와 동작 동일하므로 실질적 문제 없음.
