1. 요구한 기능
================================================================

[기능 A] Spot.cs - Inspector 상태 표시
  - Spot 컴포넌트를 Inspector에서 볼 때 현재 BuildingState가 무엇인지 실시간으로 확인 가능하게 한다.

[기능 B] TestingSpotState.cs - 키 입력으로 BuildingState 변경
  - 씬에서 특정 Building(Spot)을 하나 선택(참조)해 둔다.
  - 플레이 중 키보드 A를 누르면, 해당 Spot의 BuildingState를 Selected로 바꾼다.

2. 현재 상황 및 코드
================================================================

[Spot.cs] - Assets/Scripts/StrategyGame/Core/PathFinder/Spot.cs
  - BuildingType, BuildingState 열거형(enum)은 이미 정의되어 있음.
  - Spot 클래스에는 _spotType(BuildingType)만 SerializeField로 선언됨.
  - _buildingState 필드가 없음 → Inspector에서 현재 State를 볼 수 없음.
  - 상태를 읽거나 쓰는 Property/Method가 없음.

  현재 Spot 클래스 핵심 코드:
    [SerializeField] BuildingType _spotType;
    public BuildingType SpotType => _spotType;
    public void SetType(BuildingType type) { _spotType = type; }

[TestingSpotState.cs] - Assets/Scripts/StrategyGame/Test/TestingSpotState.cs
  - Start(), Update() 빈 껍데기만 있음. 아무 기능 없음.

[BuildingState enum] (Spot.cs 상단에 정의)
  Idle / Incident / Unselected / Selected / Completed

3. 구현 방향 (d)
================================================================

[Spot.cs 수정]
  - _buildingState 필드를 [SerializeField]로 추가.
    → Inspector에서 현재 State 확인 가능.
  - State를 읽는 Property(BuildingState CurrentState)를 추가.
  - State를 쓰는 메서드(SetState(BuildingState state))를 추가.
    → 외부(TestingSpotState 등)에서 상태 변경 가능.

[TestingSpotState.cs 수정]
  - [SerializeField] Spot _targetSpot 필드 추가.
    → Inspector에서 테스트 대상 Spot을 드래그 연결.
  - Update()에서 Input.GetKeyDown(KeyCode.A) 감지.
    → A 키 입력 시 _targetSpot.SetState(BuildingState.Selected) 호출.

4. 방식 선택 근거 (e)
================================================================

[대안 1] BuildingState를 public으로 직접 노출
  → Inspector에서 임의로 값이 바뀔 수 있어 의도치 않은 상태 변경 위험.
  → 채택 안 함.

[대안 2] [SerializeField] + private + Property + SetState 메서드 (채택)
  → Inspector에서 읽기(확인)는 가능하되, 코드를 통해서만 상태를 변경하도록 캡슐화.
  → 향후 SetState 내부에서 상태 변경 시 로직(이벤트, 비주얼 갱신 등) 추가 확장에 적합.
  → 현재 프로젝트 구조(SpotVisualConfig 등)와 일관성 있음.

[대안 3] Custom Editor로 ReadOnly 표시
  → 오버엔지니어링. 단순 확인 목적에는 [SerializeField]로 충분.
  → 채택 안 함.

[TestingSpotState 방식]
  - Input.GetKeyDown: 단순 테스트 목적에 적합. 새 InputSystem 불필요.
  - Spot 참조를 Inspector에서 드래그 연결: 씬에서 원하는 Building을 자유롭게 교체 가능.

6. 변경 위치 및 내용 (g)
================================================================

[파일: Spot.cs]
  변경 전:
    [SerializeField] BuildingType _spotType;
    public BuildingType SpotType => _spotType;
    public void SetType(BuildingType type) { _spotType = type; }

  변경 후 (추가):
    [SerializeField] BuildingType _spotType;
    [SerializeField] BuildingState _buildingState;   ← 추가 (Inspector 확인용)

    public BuildingType SpotType => _spotType;
    public BuildingState CurrentState => _buildingState;  ← 추가

    public void SetType(BuildingType type) { _spotType = type; }
    public void SetState(BuildingState state) { _buildingState = state; }  ← 추가

[파일: TestingSpotState.cs]
  변경 전:
    (Start, Update 빈 껍데기)

  변경 후:
    [SerializeField] Spot _targetSpot;

    void Update()
    {
        if (Input.GetKeyDown(KeyCode.A))
        {
            if (_targetSpot != null)
                _targetSpot.SetState(BuildingState.Selected);
        }
    }

7. 주의할 점 (h)
================================================================

  1. _buildingState는 [SerializeField]이므로 Inspector에서 직접 수정 가능하다.
     → 테스트 중 Inspector 값을 실수로 바꾸지 않도록 주의.
     → 향후 실제 게임 로직 적용 시 Inspector 편집을 막으려면
        [field: SerializeField] + HideInInspector 또는 Custom Editor를 고려.

  2. TestingSpotState.cs는 TESTING 네임스페이스 내에 있음.
     → Spot 클래스는 네임스페이스 없이 전역으로 선언되어 있으므로
        using 선언 없이 접근 가능. 문제 없음.

  3. Input.GetKeyDown은 구 InputSystem 기준.
     → 프로젝트에 새 Input System 패키지가 활성화된 경우
        키 입력이 동작하지 않을 수 있음.
        (현재 프로젝트 패키지 설정 확인 필요)

  4. 플레이 모드에서 Inspector 확인 시, _buildingState 값이 바뀌는 것을
     실시간으로 볼 수 있으나, 플레이 종료 후에는 변경 값이 리셋됨.
     (SerializeField의 플레이모드 동작 특성)
