b. 요구한 기능
================================================================

  [ B 조합 = ① 경로탐색(BFS) + ② 오디오 ]

  ① PathFinder (경로탐색)
     - 씬에 노드(Node)들을 배치하고 연결해
       두 노드 사이의 최단 경로를 BFS로 계산한다
     - 캐릭터/유닛의 맵 이동 경로 계산에 사용
     - 노드 간 방향(단방향/양방향) 설정 가능

  ② SoundManager (오디오)
     - BGM(배경음악) 재생/정지/루프 제어
     - SFX(효과음) 라운드로빈 방식으로 겹침 없이 재생
     - TriggerSFX를 씬 오브젝트에 부착해 이벤트 기반 사운드 트리거 가능

  [ 특징 ]
  - B 조합의 두 시스템은 C 조합(GameManager, DayManager 등)에
    전혀 의존하지 않는다 → 독립적으로 추가/테스트 가능

e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

  Q. Node 오브젝트를 프리팹으로 만들지 않는 이유?
  ─────────────────────────────────────────────────
  ✅ B 조합 단계에서는 "경로 계산이 동작하는지" 검증이 목적.
     프리팹 제작은 실제 맵 설계 시(⑨ UI/View 조합)에 하는 것이 효율적.
     지금은 Inspector 직결 구성으로 최소한의 테스트만 진행.

  Q. SFX AudioSource를 별도 자식 오브젝트로 분리하지 않는 이유?
  ──────────────────────────────────────────────────────────────
  ✅ SoundManager가 List<AudioSource>를 Inspector에서 받으므로,
     같은 GameObject에 여러 AudioSource를 추가해도 동작한다.
     원본 GameDispatchLike 구성 방식을 그대로 따른다.

  Q. TriggerSFX.cs를 General 폴더 대신 Audio 폴더에 넣는 이유?
  ────────────────────────────────────────────────────────────────
  ✅ TriggerSFX는 SoundManager를 직접 호출하는 오디오 전용 헬퍼이다.
     기능 기준으로 Audio 폴더에 넣는 것이 프로젝트 폴더 구조와 일관성이 있다.

  Q. Node.cs의 디버그 컴포넌트(_circle, _txtNumber)를 삭제하지 않는 이유?
  ──────────────────────────────────────────────────────────────────────────
  ✅ 나중에 맵 에디팅 시 디버그 시각화가 유용하다.
     _debug = false로 두면 런타임 동작에 영향 없으므로 유지.
     단, OnValidate의 NullRef 가능성은 수정 필요 (h 참조).

h. 주의할 점
================================================================

  ① Node.cs의 using UnityEngine.Experimental.GlobalIllumination 반드시 제거
  ──────────────────────────────────────────────────────────────────────────
  Unity 6에서 해당 네임스페이스는 deprecated되어 없거나 경고가 뜬다.
  Node.cs 코드 어디에서도 이 네임스페이스를 실제로 사용하지 않으므로
  복사 직후 즉시 제거한다.

  ② Node.cs OnValidate의 _circle NullReference 가능성
  ───────────────────────────────────────────────────────
  Node.cs의 OnValidate()에서 _debug = false일 때
    _circle.gameObject.SetActive(false)
  를 호출한다. _circle이 Inspector에서 연결되지 않으면 NullRef 발생.

  에디터에서 Node를 만들면 Inspector에 _circle 필드가 보이는데,
  아무것도 연결하지 않으면 OnValidate에서 에러가 출력된다.
  (런타임 에러는 아니지만 에디터에서 Console 에러로 표시됨)

  두 가지 대응 방법:
    방법 A: _circle을 null 체크하도록 Node.cs 수정
            if (_circle != null) _circle.gameObject.SetActive(false);
    방법 B: 각 Node 오브젝트 하위에 빈 오브젝트를 만들어 _circle에 연결

  방법 A가 더 간단하다. 복사 시 함께 수정 권장.

  ③ SoundManager _sfxAudioSources는 비어있으면 즉시 에러
  ──────────────────────────────────────────────────────
  PlaySFX() 호출 시 _sfxAudioSources[_currentSFXAudioSource]를 인덱스 접근한다.
  List가 비어있으면 ArgumentOutOfRangeException.
  씬 구성 후 반드시 Inspector에서 AudioSource 최소 1개 이상 연결할 것.
  (Play 버튼만 누르고 PlaySFX를 직접 호출하지 않으면 에러 없음)

  ④ PathFinderManager.nodesParent 미연결 시 Start()에서 에러 없음
  ──────────────────────────────────────────────────────────────────
  nodesParent == null이면 Start()에서 "if (nodesParent == null) nodesParent = transform;"
  처리로 PathFinderManager 자신의 자식을 노드로 인식한다.
  → nodesParent를 연결하지 않으면 [PathFinder] 하위에 Node가 있어야 동작한다.
  → [Nodes]를 별도 오브젝트로 만들 경우 반드시 nodesParent를 연결할 것.

  ⑤ B 조합은 C 조합과 완전 독립이지만 Singleton.cs를 공유함
  ──────────────────────────────────────────────────────────
  SoundManager는 Singleton<SoundManager>를 상속한다.
  이 Singleton<T>는 C 조합에서 복사한 Utils/Singleton.cs를 사용한다.
  → Singleton.cs가 없으면 SoundManager.cs 컴파일 에러 발생.
  → C 조합이 완료된 현재 프로젝트에서는 문제 없음.

  ⑥ 각 Phase 후 반드시 Console 에러 0 확인
  ──────────────────────────────────────────
  에러가 남은 상태에서 씬을 저장하거나 Unity를 종료하면 씬 파일이
  손상될 수 있다. Phase 7-2 컴파일 확인을 반드시 통과 후 씬 작업 진행.
