b. 요구한 기능
================================================================

  [전제 상황]
    - 총 10페이지가 존재하고 PAGE_BUTTON_LIMIT = 3이라 가정
    - NavBar 구성:
        LeftEndButton | previousButton
        | [버튼1] | [버튼2] | [버튼3] |
        nextButton | RightEndButton

  [LeftEndButton]
    - 슬라이딩 윈도우의 가장 첫 번째 윈도우(windowStart = 1)로 이동
    - 해당 윈도우의 첫 번째 버튼(페이지 1)을 Selected 상태로 포커스
    - 갤러리 콘텐츠도 1페이지로 이동

    예시 (현재 윈도우가 [4,5,6]인 상태에서 클릭):
      → windowStart = 1
      → 버튼 레이블 [1, 2, 3]으로 갱신
      → 갤러리 1페이지 이미지 표시
      → "1" 버튼 Selected 상태

  [RightEndButton]
    - 슬라이딩 윈도우의 가장 마지막 윈도우로 이동
    - 해당 윈도우의 마지막 활성 버튼(maxPages 번 페이지)을 Selected 상태로 포커스
    - 갤러리 콘텐츠도 maxPages 페이지로 이동

    예시 (maxPages=10, PAGE_BUTTON_LIMIT=3, 현재 윈도우가 [1,2,3]):
      → lastWindowStart = ((10-1)/3)*3 + 1 = 10
      → windowStart = 10
      → 버튼 레이블 [10, -, -] (11, 12는 존재하지 않아 비활성)
      → 갤러리 10페이지 이미지 표시
      → "10" 버튼 Selected 상태

  [interactable 조건]
    - LeftEndButton  : windowStart > 1 일 때만 interactable
                       (= previousButton과 동일 조건)
    - RightEndButton : windowStart + pageButtons.Count <= maxPages 일 때만 interactable
                       (= nextButton과 동일 조건)
    - 두 버튼 모두 UpdateNavBarWindow()에서 일괄 갱신

c. 현재 상황 및 코드
================================================================

  [ GalleryMenu.cs 현재 코드 중 관련 부분 ]

  // 필드: 이미 선언되어 있음 (onClick은 미등록 상태)
  [SerializeField] private Button LeftEndButton;
  [SerializeField] private Button RightEndButton;

  // ConstructNavBar(): LeftEndButton/RightEndButton onClick 등록 없음
  private void ConstructNavBar()
  {
      ...
      for(int i = 1; i <= pageLimit; i++)
      {
          GameObject buttonOB = Instantiate(panelSelectionPrefab.gameObject, panelSelectionPrefab.transform.parent);
          buttonOB.SetActive(true);
          Button button = buttonOB.GetComponent<Button>();
          buttonOB.name = i.ToString();
          pageButtons.Add(button);
      }
      ArrangeNavBarOrder();
      UpdateNavBarWindow();          // ← windowStart 기준으로 버튼 레이블/리스너/활성 갱신
  }

  // UpdateNavBarWindow(): LeftEndButton/RightEndButton interactable 갱신 없음
  private void UpdateNavBarWindow()
  {
      for (int i = 0; i < pageButtons.Count; i++)
      {
          int page = windowStart + i;
          pageButtons[i].onClick.RemoveAllListeners();
          pageButtons[i].onClick.AddListener(() => LoadPage(page));
          pageButtons[i].GetComponentInChildren<TextMeshProUGUI>().text = page.ToString();
          pageButtons[i].gameObject.SetActive(page <= maxPages);
      }
      previousButton.interactable = (windowStart > 1);
      nextButton.interactable = (windowStart + pageButtons.Count <= maxPages);
      // LeftEndButton, RightEndButton interactable 미설정 ← 문제
  }

  [ 문제 요약 ]
    ① LeftEndButton, RightEndButton에 onClick 리스너가 전혀 등록되지 않아
       클릭해도 아무 동작도 하지 않는다.

    ② UpdateNavBarWindow()에서 두 버튼의 interactable 상태를 갱신하지 않아
       윈도우 위치에 관계없이 항상 클릭 가능 상태다.

d. 요구한 기능을 만들기 위해서 어떤 식으로 생성하거나 변경해야 하는지
================================================================

  [핵심 메커니즘]
    두 버튼의 onClick은 ConstructNavBar() 내에서 1회만 등록한다.
    (리스너 내용이 windowStart와 무관하게 고정된 동작이므로
     매 UpdateNavBarWindow()마다 재등록할 필요가 없다.)

    interactable 상태는 UpdateNavBarWindow()에 두 줄 추가해 일괄 갱신한다.

  [1] ConstructNavBar()에 onClick 등록 추가

      LeftEndButton.onClick.AddListener(ToLeftEnd);
      RightEndButton.onClick.AddListener(ToRightEnd);

  [2] ToLeftEnd() 메서드 추가

      public void ToLeftEnd()
      {
          windowStart = 1;
          UpdateNavBarWindow();
          LoadPage(1);
          StartCoroutine(SelectPageButtonNextFrame(1));
      }

  [3] ToRightEnd() 메서드 추가

      public void ToRightEnd()
      {
          // 마지막 윈도우의 첫 페이지 번호 계산
          int lastWindowStart = ((maxPages - 1) / PAGE_BUTTON_LIMIT) * PAGE_BUTTON_LIMIT + 1;
          windowStart = lastWindowStart;
          UpdateNavBarWindow();
          LoadPage(maxPages);
          StartCoroutine(SelectPageButtonNextFrame(maxPages));
      }

  [4] UpdateNavBarWindow()에 interactable 갱신 추가

      private void UpdateNavBarWindow()
      {
          ...
          previousButton.interactable  = (windowStart > 1);
          nextButton.interactable       = (windowStart + pageButtons.Count <= maxPages);
          // ↓ 추가
          LeftEndButton.interactable    = (windowStart > 1);
          RightEndButton.interactable   = (windowStart + pageButtons.Count <= maxPages);
      }

  [ lastWindowStart 계산 근거 ]
    maxPages=10, PAGE_BUTTON_LIMIT=3:
      ((10-1)/3)*3 + 1  =  (9/3)*3 + 1  =  9 + 1  = 10  ✓
    maxPages=9, PAGE_BUTTON_LIMIT=3:
      ((9-1)/3)*3 + 1   =  (8/3)*3 + 1  =  6 + 1  =  7  ✓
    maxPages=3, PAGE_BUTTON_LIMIT=3:
      ((3-1)/3)*3 + 1   =  (2/3)*3 + 1  =  0 + 1  =  1  ✓
    ※ C# 정수 나눗셈(버림)을 이용한 공식

================================================================
e. 다른 방법들 중에서 왜 d의 방식으로 만든 것인지
================================================================

[ 방법 A: Inspector에서 onClick 직접 연결 (드래그앤드롭) ]

  방식
    - Unity Inspector에서 LeftEndButton의 OnClick()에
      GalleryMenu.ToLeftEnd 메서드를 직접 연결

  장점
  ✓ 코드 변경 최소화

  단점
  ✗ ToLeftEnd/ToRightEnd를 public으로 선언해야 하는 것은 동일
  ✗ 리스너가 Inspector에 있어 코드만 보면 동작을 알 수 없음
  ✗ 기존 nextButton/previousButton 리스너도 Inspector에 없고
    현재 프로젝트는 코드 등록 방식을 사용 중 → 방식 불일치

[ 방법 B (채택): ConstructNavBar()에서 코드로 onClick 등록 ]

  방식
    - ConstructNavBar() 내에서 AddListener로 리스너 등록
    - 기존 nextButton/previousButton 등록 방식과 동일

  장점
  ✓ 프로젝트의 기존 방식과 일관성 유지
  ✓ 리스너가 코드 한 곳에 집중 → 가독성·유지보수 우수
  ✓ ToLeftEnd/ToRightEnd를 private으로 선언 가능
    (Inspector에서 호출하지 않으므로 public 불필요)
  ✓ 씬 재로드 없이도 항상 정상 작동 보장

  단점
  - 리스너를 ConstructNavBar()에서 1회 추가하지 않으면 동작 안 함
    (ConstructNavBar는 Initialize() 내에서 반드시 호출되므로 누락 위험 낮음)

  → 방법 B 채택. 기존 방식과 일관성을 유지하고 캡슐화가 우수하다.

f. 어떤 순서로 진행할 것인지
================================================================

  [코드 변경]
  1. UpdateNavBarWindow()에 두 줄 추가
       LeftEndButton.interactable  = (windowStart > 1);
       RightEndButton.interactable = (windowStart + pageButtons.Count <= maxPages);

  2. ToLeftEnd() 메서드 추가
       (ToNextPage/ToPreviousPage 근처에 배치)

  3. ToRightEnd() 메서드 추가
       (ToLeftEnd 바로 아래에 배치)

  4. ConstructNavBar()에 onClick 등록 추가
       UpdateNavBarWindow() 호출 바로 위에 삽입
       LeftEndButton.onClick.AddListener(ToLeftEnd);
       RightEndButton.onClick.AddListener(ToRightEnd);

  [테스트]
  5. Unity 실행 → 갤러리 진입 (maxPages > PAGE_BUTTON_LIMIT 상황)
       - LeftEndButton  interactable=false 확인 (이미 첫 윈도우)
       - RightEndButton interactable=true  확인

  6. RightEndButton 클릭
       - 마지막 윈도우로 이동 확인
       - 마지막 페이지 이미지 표시 확인
       - 마지막 페이지 버튼 Selected 확인
       - RightEndButton interactable=false 확인
       - LeftEndButton  interactable=true  확인

  7. LeftEndButton 클릭
       - 첫 윈도우 [1,2,3]으로 복귀 확인
       - 1페이지 이미지 표시 확인
       - "1" 버튼 Selected 확인
       - LeftEndButton  interactable=false 확인
       - RightEndButton interactable=true  확인

  8. maxPages <= PAGE_BUTTON_LIMIT 인 경우 (윈도우가 1개뿐)
       - LeftEndButton  interactable=false 확인
       - RightEndButton interactable=false 확인

  9. 이미지 클릭 → 미리보기 → 닫기
       - HidePreviewImage에서 SelectPageButton(selectedPage) 정상 동작 확인
       (RightEndButton으로 이동 후 미리보기를 열고 닫는 경우 포함)
