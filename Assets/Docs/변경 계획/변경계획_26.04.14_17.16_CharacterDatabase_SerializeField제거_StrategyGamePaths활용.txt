CharacterDatabase에서 Inspector를 통해 직접 입력받던 _charactersFolder 경로 문자열을
StrategyGamePaths 상수 클래스에서 읽어오도록 변경.

- Inspector에서 직접 문자열을 입력하는 방식 제거
- VisualNovel의 FilePaths.cs와 동일한 패턴으로, StrategyGamePaths.cs에 경로를 미리 정의
- CharacterDatabase는 해당 상수를 참조만 함

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ CharacterDatabase.cs
  경로: Assets/Scripts/StrategyGame/Core/Character/CharacterDatabase.cs

  [SerializeField] private string _charactersFolder;   // ← Inspector에서 수동 입력

  private void Awake()
  {
      _characterSOs = new Dictionary<string, CharacterSO>();
      var characterList = Resources.LoadAll<CharacterSO>(_charactersFolder).ToList();
      characterList.ForEach(c => { _characterSOs.Add(c.ID, c); });
  }

  문제: Inspector에서 사람이 직접 입력하므로 오타, 공백, 대소문자 실수 등으로
        Resources.LoadAll이 빈 배열을 반환할 위험이 있다.
        씬/프리팹마다 값이 달라질 수도 있다.

■ StrategyGamePaths.cs (이미 존재)
  경로: Assets/Scripts/StrategyGame/Core/Utils/StrategyGamePaths.cs

  public static class StrategyGamePaths
  {
      private const string RESOURCES_ROOT = "StrategyGame/";

      public const string Characters   = RESOURCES_ROOT + "Characters";   // "StrategyGame/Characters"
      public const string PlayerLevels = RESOURCES_ROOT + "PlayerLevels";
  }

  → Characters 상수가 이미 정의되어 있음.
    CharacterDatabase가 참조할 준비가 되어 있다.

d. 구현 방식
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
StrategyGamePaths.cs는 이미 Characters 상수를 보유하고 있으므로
별도 추가 없이, CharacterDatabase.cs만 수정한다.

변경 내용:
  1. [SerializeField] private string _charactersFolder; 필드 전체 삭제
  2. Awake 안의 Resources.LoadAll<CharacterSO>(_charactersFolder)를
     Resources.LoadAll<CharacterSO>(StrategyGamePaths.Characters)로 교체

e. 해당 방식을 선택한 이유
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
고려한 방법들:

  [방법 A] 현행 유지 (SerializeField)
    - 장점: Inspector에서 바로 확인 가능
    - 단점: 오타/공백/대소문자 실수 위험, 씬마다 값이 달라질 수 있음,
            경로 변경 시 모든 씬·프리팹을 일일이 수정해야 함

  [방법 B] CharacterDatabase 안에 private const 하드코딩
    - 장점: SerializeField보다는 안전
    - 단점: 경로 관리가 분산됨. 같은 경로를 다른 스크립트에서 또 쓸 경우 중복 발생

  [방법 C] StrategyGamePaths.cs 상수 참조 ← 채택
    - 장점:
        · 프로젝트 내 경로를 한 파일(StrategyGamePaths.cs)에서 중앙 관리
        · 경로 변경 시 StrategyGamePaths.cs 한 곳만 수정하면 전체 반영
        · FilePaths.cs(VisualNovel)와 동일한 패턴으로 팀 내 일관성 유지
        · Inspector 실수 원천 차단
        · StrategyGamePaths.Characters가 이미 올바른 값으로 정의되어 있어
          추가 작업 없이 바로 연결 가능
    - 단점: Inspector에서 경로가 보이지 않음
            (→ StrategyGamePaths.cs를 보면 되므로 실질적 문제 없음)

  방법 C가 가장 리스크가 낮고 기존 설계 방향과 일치하므로 채택.

h. 주의할 점
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  1. 실제 Resources 폴더 경로 일치 여부 확인 필수
     StrategyGamePaths.Characters = "StrategyGame/Characters"
     → 실제 폴더: Assets/Resources/StrategyGame/Characters/
     이 폴더가 없거나 이름이 다르면 LoadAll이 빈 배열을 반환하며 조용히 실패한다.

  2. 기존 씬/프리팹에 저장된 _charactersFolder 직렬화 값 소멸
     SerializeField를 제거하면 씬·프리팹에 저장된 문자열 값은 사라진다.
     하지만 이후에는 상수를 사용하므로 해당 값이 더 이상 필요하지 않다.
     (이전에 Inspector에서 잘못 입력된 값이 있었다면 오히려 정리된다.)

  3. 이 변경 후 _charactersFolder를 참조하는 다른 스크립트가 있다면 함께 수정 필요
     (현재 확인된 참조: CharacterDatabase.cs 내부에만 존재)

  4. StrategyGamePaths.Characters 경로를 변경할 경우
     Resources 폴더 구조도 함께 변경해야 한다.
     상수 이름은 그대로 두고 값만 바꾸면 CharacterDatabase는 자동 반영된다.
