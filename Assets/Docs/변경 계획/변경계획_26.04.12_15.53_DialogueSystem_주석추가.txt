d. 변경 방식
================================================================================

  - 기존 코드 로직 변경 없음. 주석만 추가.
  - 주석 위치:
      1) 클래스 선언 바로 위 → 블록 주석 (/* ... */)으로 전체 역할 설명
      2) 필드/프로퍼티 위 또는 옆 → 인라인 주석 (//)
      3) 메서드 선언 바로 위 → 블록 주석으로 역할/매개변수/반환값 설명
      4) 복잡한 로직 라인 옆 → 인라인 주석으로 의도 설명
  - 언어: 한국어 (기존 관례 유지)
  - 기존 영어/한국어 인라인 주석은 보존하거나 보강


================================================================================
e. 다른 방법과 비교 / 이 방식을 선택한 이유
================================================================================

  이전 VNManager 주석 작업(26.04.12_15.00)에서 결정한 방식과 동일:

  [방법 A] XML 문서 주석 (/// <summary>) → 오버엔지니어링, 채택 X
  [방법 B] 코드 리팩토링 병행           → 요구 범위 초과, 채택 X
  [방법 C] 별도 Wiki 문서로만 정리       → 코드 내 맥락 부재, 채택 X
  ★ [방법 D] 인라인 한국어 블록/라인 주석 → 채택

  DialogueSystem은 VNManager보다 복잡도가 높으므로
  특히 ConversationManager의 메인 루프(RunningConversation)와
  파싱 흐름(DialogueParser → DIALOGUE_LINE → DL_*)에
  더 많은 흐름 설명 주석을 추가한다.

h. 주의할 점
================================================================================

  1. 코드 로직 변경 없음
     - 주석만 추가. 변수명, 메서드 시그니처, 실행 순서 모두 유지.

  2. DL_Dialogue_Data.cs의 기존 한국어 주석 보존
     - StartSignal.N 추가 관련 기존 한국어 주석은 보강만 하고 삭제하지 않음.

  3. DialogueParser.cs의 TagManager.Inject 이중 호출 (주석 중요)
     - Parse() 내에서 commands = TagManager.Inject(commands) 가 두 번 호출됨.
     - 첫 번째 호출은 의도된 것 (코드 내 설명 주석 유지).
     - 두 번째 호출이 실제 동작하는 호출.
     - 주석에서 이 점을 명확히 표기할 것.

  4. ConversationManager의 userPrompt 플래그 동시성 주의
     - Unity 코루틴은 단일 스레드이므로 실제 동시성 문제는 없음.
     - 그러나 코루틴이 yield return 하는 순간에만 다른 코루틴이 실행됨.
     - userPrompt = true 가 설정되는 타이밍과 소비되는 타이밍을 주석에 명시.

  5. AutoReader.AutoRead()의 timeStarted 보정 로직
     - 텍스트 출력(isBuilding) 시간이 읽기 대기 시간에서 차감됨.
     - 이 보정을 제거하면 빠른 대사에서도 최소 MIN_READ_TIME(1초) 대기.

  6. DialogueContinuePrompt.Show()의 ForceMeshUpdate() 필요성
     - TMP는 텍스트가 변경돼도 즉시 textInfo를 업데이트하지 않음.
     - ForceMeshUpdate()를 호출해야 characterInfo가 최신 상태로 갱신됨.

  7. DL_SPEAKER_DATA의 XML summary 주석 유지
     - displayname 프로퍼티의 기존 XML summary는 삭제하지 않고 보강.
