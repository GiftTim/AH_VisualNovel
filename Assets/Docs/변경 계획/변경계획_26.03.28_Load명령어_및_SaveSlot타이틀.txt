[ 방법 선택 이유 ]

  채택: 콜론 구분 방식  Load(Chapter1: Coffee_Bean)

  - 다이얼로그 파일 작성 시 직관적이고 간결함

  비교 대상 방법들

  A) 플래그 방식: Load(-f Coffee_Bean -folder Chapter1)
     - 기존 스타일과 통일성은 있으나 작성이 장황해짐

  B) 슬래시 경로 방식: Load(Chapter1/Coffee_Bean)
     - 구현이 가장 단순하지만
       폴더/파일 구분이 시각적으로 불명확

[ 변경 후 코드 ]
  -------------------------------------------------------
  private static void LoadNewDialogueFile(string[] data)
  {
      string fileName = string.Empty;
      string folderName = string.Empty;
      bool enqueue = false;

      var parameters = ConvertDataToParameters(data);

      // 콜론으로 끝나는 인자를 폴더명으로 감지
      foreach (string arg in data)
      {
          if (arg.EndsWith(":"))
          {
              folderName = arg.TrimEnd(':');
              break;
          }
      }

      parameters.TryGetValue(PARAM_FILEPATH, out fileName);
      parameters.TryGetValue(PARAM_ENQUEUE, out enqueue, defaultValue: false);

      string resourcePath = string.IsNullOrEmpty(folderName)
          ? FilePaths.GetPathToResource(FilePaths.resources_dialogueFiles, fileName)
          : FilePaths.GetPathToResource(FilePaths.resources_dialogueFiles, $"{folderName}/{fileName}");

      TextAsset file = Resources.Load<TextAsset>(resourcePath);

      if (file == null)
      {
          Debug.LogError($"대화 파일에서 '{resourcePath}' 파일을 불러올 수 없습니다.");
          return;
      }

      List<string> lines = FileManager.ReadTextAsset(file, includeBlackLines: true);
      Conversation newComversation = new Conversation(lines);

      if (enqueue)
          DialogueSystem.instance.conversationManager.Enqueue(newComversation);
      else
          DialogueSystem.instance.conversationManager.StartConversation(newComversation);
  }
  -------------------------------------------------------

[ 사용 예시 ]
  - load(Coffee_Bean)               → Dialogue Files/Coffee_Bean
  - load(Chapter1: Coffee_Bean)     → Dialogue Files/Chapter1/Coffee_Bean
  - load(Chapter2: Ending_A)        → Dialogue Files/Chapter2/Ending_A

  2. SaveLoadSlot 타이틀에 폴더명 표시
================================================================

[ 현재 동작 ]
  - 세이브 슬롯에 데이터가 있으면 titleText = "{fileNumber}."
  - 어느 챕터/폴더의 파일인지 알 수 없음

[ 목표 동작 ]
  - titleText = "{fileNumber}. [Chapter1]" 처럼
    현재 진행 중인 다이얼로그 파일이 속한 폴더명을 함께 표시
  - 폴더명을 알 수 없으면 기존과 동일하게 "{fileNumber}." 표시

----------------------------------------------------------------

[ 데이터 흐름 설명 ]
  세이브 시
    VNGameSave.Save()
      → GetConversationData()
        → conversation.file 에서 리소스 경로 저장
           예: "Dialogue Files/Chapter1/Coffee_Bean"
        → VN_ConversationDataCompressed.fileName 에 담아 JSON 직렬화
        → activeConversations[0] 에 저장됨

  슬롯 표시 시
    SaveLoadSlot.PopulateDetailsFromFile()
      → file.activeConversations[0] 역직렬화
        → fileName = "Dialogue Files/Chapter1/Coffee_Bean"
        → "Dialogue Files/" 제거 → "Chapter1/Coffee_Bean"
        → 첫 번째 '/' 앞 부분 추출 → "Chapter1"
        → titleText 에 표시

----------------------------------------------------------------

[ 방법 선택 이유 ]
  - VNGameSave에 별도 필드(chapaterName 등)를 추가하지 않아도 됨
  - 이미 저장되는 activeConversations 데이터를 재활용
  - 기존 세이브 파일과 완전 호환 (새 필드 없음)

----------------------------------------------------------------

  // 추가 헬퍼 메서드
  private string GetFolderLabelFromSave(VNGameSave file)
  {
      if (file.activeConversations == null || file.activeConversations.Length == 0)
          return string.Empty;

      try
      {
          var compressed = JsonUtility.FromJson<VN_ConversationDataCompressed>(file.activeConversations[0]);
          if (compressed == null || string.IsNullOrEmpty(compressed.fileName))
              return string.Empty;

          // "Dialogue Files/Chapter1/Coffee_Bean" → "Chapter1"
          string prefix = FilePaths.resources_dialogueFiles; // "Dialogue Files/"
          string withoutPrefix = compressed.fileName.StartsWith(prefix)
              ? compressed.fileName.Substring(prefix.Length)
              : compressed.fileName;

          int slashIndex = withoutPrefix.IndexOf('/');
          return slashIndex > 0 ? withoutPrefix.Substring(0, slashIndex) : string.Empty;
      }
      catch
      {
          return string.Empty;
      }
  }
